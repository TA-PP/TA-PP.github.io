## 문제 정의

[백준 1202번 보석 도둑](https://www.acmicpc.net/problem/1202)은 무게와 가격이 서로 다른 보석 `N`개와 최대 수용 무게가 정해진 가방 `K`개가 주어질 때, 훔칠 수 있는 보석 가격의 최댓값을 구하는 문제다.

각 가방에는 보석을 최대 하나만 넣을 수 있고, 하나의 보석도 한 번만 사용할 수 있다. 따라서 단순히 가격이 비싼 보석부터 고르면 해당 보석이 들어갈 가방을 효율적으로 찾아야 하고, 가방마다 모든 보석을 다시 확인하면 입력이 클 때 시간 초과가 발생한다.

이 문제에서는 서로 다른 두 기준을 함께 다뤄야 한다.

- **무게:** 현재 가방에 넣을 수 있는 보석인지 판단하는 기준
- **가격:** 넣을 수 있는 보석 중 무엇을 선택할지 결정하는 기준

무게 기준 탐색은 정렬과 덱으로, 가격 기준 선택은 최대 힙으로 분리하는 것이 핵심이다.

## 접근 및 설계

처음에 보석과 가방을 모두 정렬해야 한다는 점까지는 생각했다.

```python
jewels.sort(key=lambda x: x[0])
bags.sort()
```

하지만 정렬한 다음 어떤 보석을 후보로 옮기고, 후보 중 하나를 어떻게 선택해야 하는지가 바로 떠오르지 않았다.

정렬 이후의 과정을 두 질문으로 나누면 설계가 선명해진다.

```text
1. 현재 가방에 들어갈 수 있는 보석은 어디까지인가?
2. 그 보석들 중 어떤 것을 가져가야 이익이 최대인가?
```

### 1. 가장 작은 가방부터 확인한다

가방을 수용 무게 오름차순으로 처리한다.

작은 가방에 들어갈 수 있는 보석은 이후의 더 큰 가방에도 들어갈 수 있다. 따라서 현재 가방에서 선택하지 않은 후보를 버리지 않고 다음 가방으로 넘길 수 있다.

반대로 큰 가방부터 처리하면 그 가방에만 들어가는 무거운 보석과 작은 가방에도 들어가는 가벼운 보석을 함께 비교하게 된다. 여기서 가벼운 보석을 선택하면 작은 가방에 넣을 기회를 불필요하게 잃을 수 있다.

### 2. 현재 가방에 들어가는 보석을 모두 후보에 추가한다

보석은 무게 오름차순으로 정렬했다. 가장 앞에 있는 보석부터 확인하면서 무게가 현재 가방의 용량보다 작거나 같으면 가격을 힙에 넣는다.

```python
while jewels:
    mass, value = jewels[0]

    if mass <= bag:
        heapq.heappush(heap, -value)
        jewels.popleft()
    else:
        break
```

앞의 보석이 너무 무겁다면 뒤의 보석은 무게가 같거나 더 무거우므로 현재 가방에는 들어갈 수 없다. 따라서 즉시 반복을 멈출 수 있다.

한 번 후보 힙으로 옮긴 보석은 원래 덱으로 돌아갈 필요가 없다. 다음 가방은 현재 가방보다 크거나 같으므로, 지금 들어가는 보석은 다음 가방에도 들어가기 때문이다.

### 3. 후보 중 가장 비싼 보석을 꺼낸다

현재 가방에 들어갈 수 있는 모든 보석을 후보로 옮겼다면 그중 가격이 가장 높은 보석 하나를 선택한다.

Python의 `heapq`는 최소 힙만 제공한다. 가격에 음수를 붙여 저장하면 실제 가격이 가장 큰 보석이 힙에서는 가장 작은 값이 된다.

```text
실제 가격: 100, 70, 50
힙 저장값: -100, -70, -50

최소 힙에서 먼저 나오는 값: -100
실제 선택 가격: -(-100) = 100
```

```python
heapq.heappush(heap, -value)

if heap:
    result += -heapq.heappop(heap)
```

여기서 꺼내는 것은 최소 가격이 아니라 **음수로 변환된 값 중 최솟값**, 즉 원래 가격의 최댓값이다.

### 예시로 보는 후보 이동

다음 보석과 가방이 있다고 하자.

```text
보석: (무게 1, 가격 65), (무게 2, 가격 99), (무게 5, 가격 23)
가방: 2, 10
```

```text
[가방 용량 2]
들어갈 수 있는 보석: (1, 65), (2, 99)
가격 후보 힙: 65, 99
가장 비싼 99 선택
힙에 65가 남음

[가방 용량 10]
새로 들어갈 수 있는 보석: (5, 23)
가격 후보 힙: 65, 23
가장 비싼 65 선택

총 가격: 99 + 65 = 164
```

앞 가방에서 선택하지 않은 보석도 다음 가방의 후보로 남아 있기 때문에 같은 보석을 다시 탐색할 필요가 없다.

### 왜 작은 가방에서 가장 비싼 후보를 골라도 되는가

가장 작은 가방에 들어갈 수 있는 보석 중 가장 비싼 보석을 `A`라고 하자. 어떤 최적해가 작은 가방에 다른 보석 `B`를 넣었다면 `A`와 `B`를 바꿔도 가격 합은 줄어들지 않는다.

만약 `A`가 더 큰 가방에 들어 있었다면, 작은 가방에 들어갔던 `B`는 무게가 작은 가방의 용량 이하이므로 그보다 큰 가방에도 들어간다. 두 보석의 위치를 교환할 수 있다.

`A`가 사용되지 않았다면 작은 가방의 `B` 대신 `A`를 넣으면 된다. 어느 경우든 가방 제한을 위반하지 않으며 총가격은 더 커지거나 같다.

따라서 작은 가방부터 가능한 보석 중 가장 비싼 것을 선택하는 그리디 전략이 최적해를 만든다.

## 사용한 자료구조

### 리스트(List)

보석은 `(무게, 가격)` 쌍으로, 가방은 수용 가능한 최대 무게로 리스트에 저장한다.

```python
jewels.append((mass, value))
bags.append(capacity)
```

보석 리스트는 무게순, 가방 리스트는 용량순으로 정렬한다.

### 덱(Deque)

무게순으로 정렬한 보석을 `deque`로 변환한다.

```python
jewels = deque(jewels)
```

현재 가방에 들어가는 가장 가벼운 보석부터 `popleft()`로 꺼내 후보 힙에 옮긴다. `deque.popleft()`는 `O(1)`에 동작한다.

일반 리스트에서 `pop(0)`을 사용하면 뒤의 모든 원소를 한 칸씩 이동해야 하므로 한 번에 `O(N)`이 필요하다. 앞에서 원소를 반복해서 제거해야 하는 현재 구조에는 덱이 적합하다.

### 최대 힙(Max Heap)

후보 힙에는 현재 가방에 들어갈 수 있고 아직 사용하지 않은 보석의 가격을 저장한다.

Python의 `heapq`는 최소 힙이므로 가격의 부호를 반대로 저장해 최대 힙처럼 사용한다.

```python
heapq.heappush(candidates, -value)
best_value = -heapq.heappop(candidates)
```

힙에는 무게를 저장할 필요가 없다. 힙으로 이동한 시점에 이미 현재 가방에 들어간다는 검사가 끝났고, 이후 가방은 더 크므로 계속 무게 조건을 만족한다.

## 사용한 알고리즘

### 정렬(Sorting)

보석과 가방을 각각 오름차순으로 정렬한다.

```python
jewels.sort(key=lambda jewel: jewel[0])
bags.sort()
```

- 보석 무게순 정렬: 현재 가방에 들어가는 보석을 앞에서부터 연속해서 꺼낼 수 있다.
- 가방 용량순 정렬: 이전 가방의 후보를 이후 가방에서도 그대로 사용할 수 있다.

### 그리디(Greedy)

가장 작은 가방부터 현재 담을 수 있는 보석 중 가격이 가장 높은 보석을 선택한다.

작은 가방은 선택지가 적고 큰 가방은 선택지가 많다. 제약이 강한 작은 가방부터 최선의 보석을 확정하고, 선택하지 않은 후보는 다음 가방으로 넘긴다.

### 우선순위 큐(Priority Queue)

현재 가방에 들어갈 수 있는 보석 후보가 여러 개일 때 최댓값을 매번 빠르게 꺼낸다.

후보를 리스트로 관리하면서 매번 최댓값을 찾으면 가방 하나당 최대 `O(N)`이 들 수 있다. 힙을 사용하면 삽입과 최댓값 제거를 각각 `O(log N)`에 처리할 수 있다.

## 시간복잡도

- 보석 `N`개 정렬: `O(N log N)`
- 가방 `K`개 정렬: `O(K log K)`
- 각 보석을 덱에서 꺼내 힙에 한 번 삽입: 총 `O(N log N)`
- 각 가방에서 보석을 최대 한 번 선택: 총 `O(K log N)`
- 전체 시간복잡도: **`O(N log N + K log K + K log N)`**
- 공간복잡도: **`O(N + K)`**

각 보석은 덱에서 최대 한 번 꺼내지고 힙에도 최대 한 번 들어간다. 중첩된 `while`문이 있어도 가방마다 전체 보석을 처음부터 다시 탐색하는 것이 아니므로 보석 이동 횟수의 합은 `N`번이다.

## 알고리즘 흐름(텍스트 다이어그램)

```text

[가방: 용량 오름차순 정렬]
        |
        v

     Yes                         No
      |                           |
      v                           |
[가격에 음수를 붙여 힙에 추가]   |

      |                           |

                             v         v
```

## 최종 제출 코드

```python
import sys
import heapq
from collections import deque

input = sys.stdin.buffer.readline

N, K = map(int, input().split())
jewels = []
bags = []

for _ in range(N):
    mass, value = map(int, input().split())
    jewels.append((mass, value))

for _ in range(K):
    bags.append(int(input()))

jewels.sort(key=lambda jewel: jewel[0])
bags.sort()
jewels = deque(jewels)

candidates = []
result = 0

for capacity in bags:
    while jewels and jewels[0][0] <= capacity:
        _, value = jewels.popleft()
        heapq.heappush(candidates, -value)

    if candidates:
        result += -heapq.heappop(candidates)

print(result)
```

```python

```

## 오늘의 회고(실수한 점 포함)

보석과 가방을 각각 정렬해야 한다는 접근까지는 잘 잡았다. 이 문제에서 막힌 지점은 정렬 이후 어떤 자료구조로 보석을 제거하고, 현재 가방에 넣을 보석을 어떻게 선택할 것인지였다.

그 부분을 다음 두 역할로 분리하니 해결할 수 있었다.

```text
무게 조건을 만족하는 보석 이동: 정렬 + deque.popleft()
후보 중 가장 높은 가격 선택:   최대 힙
```

이번 풀이에서 복기할 내용은 다음과 같다.

1. **정렬만으로는 두 가지 기준을 동시에 처리하기 어려웠다.**

   보석을 무게순으로 정렬하면 가방에 들어가는 범위를 찾기 쉽지만 가장 비싼 보석을 바로 알 수 없다. 가격순으로 정렬하면 반대로 무게 조건을 효율적으로 관리하기 어렵다. 무게 탐색과 가격 선택을 정렬과 힙으로 나누는 것이 핵심이었다.

2. **작은 가방부터 처리해야 후보를 재사용할 수 있었다.**

   현재 가방에 들어가는 보석은 다음의 더 큰 가방에도 들어간다. 그래서 선택하지 않은 후보를 힙에 그대로 남겨 둘 수 있고, 같은 보석을 다시 검사하지 않아도 된다.

3. **최소 힙으로 최댓값을 꺼내는 변환이 필요했다.**

   Python `heapq`에서 가장 비싼 보석을 선택하려면 가격에 음수를 붙인다. “최솟값을 꺼낸다”는 힙의 동작은 그대로 두고 데이터의 부호를 바꿔 원하는 우선순위를 만든다.

4. **앞에서 반복 제거할 때는 덱이 적합했다.**

   정렬된 보석 목록의 첫 원소를 계속 제거하므로 리스트의 `pop(0)`보다 `deque.popleft()`가 효율적이다. 현재 작성한 코드에서 이 자료구조 선택은 잘 적용됐다.

5. **중첩 반복문만 보고 `O(NK)`라고 판단하면 안 된다.**

   안쪽 `while`에서 각 보석은 전체 실행 동안 한 번만 덱에서 제거된다. 반복문 모양뿐 아니라 각 원소가 총 몇 번 처리되는지 세어 시간복잡도를 계산해야 한다.

이번 문제를 통해 조건이 서로 다른 두 기준으로 구성된 그리디 문제에서는 **한 기준으로 후보 범위를 좁히고, 다른 기준을 우선순위 큐로 관리하는 방식**을 복기했다. 정렬 이후 선택 단계가 떠오르지 않을 때는 “현재 선택 가능한 후보를 어떻게 모을 것인가”와 “후보 중 최선의 값을 어떻게 빠르게 꺼낼 것인가”를 분리해서 생각하는 것이 중요하다.
