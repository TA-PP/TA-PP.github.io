## 문제 정의

길이가 서로 다른 파 `S`개를 가지고 주문받은 파닭 `C`개를 만들어야 한다. 모든 파닭에는 같은 길이의 파를 넣되, 한 마리에 넣는 파의 길이를 최대화해야 한다.

파닭을 모두 만든 뒤 남은 파의 총길이를 출력하는 문제다. 파의 길이와 자르는 길이는 모두 정수다.

예를 들어 길이가 `440`, `350`, `230`인 파로 파닭 5개를 만들 때, 파닭 한 마리에 넣을 수 있는 최대 길이는 `175`다.

```text
440 // 175 = 2개
350 // 175 = 2개
230 // 175 = 1개
총 5개
```

전체 파의 길이는 `1,020`이고 파닭에 사용한 길이는 `175 × 5 = 875`이므로, 남은 파의 길이는 `145`다.

## 접근 및 설계

파닭 한 마리에 넣을 파의 길이를 `length`라고 하면, 현재 가진 파로 만들 수 있는 조각 수는 다음과 같다.

```python
count = sum(onion // length for onion in onions)
```

`length`가 짧으면 많은 조각을 만들 수 있고, `length`가 길어지면 만들 수 있는 조각 수는 줄어든다.

```text
자를 길이:        짧음 ---------------------------> 길어짐
C개 이상 생성:    가능 가능 가능 가능 | 불가능 불가능 불가능
                                   ↑
                         찾으려는 최대 가능 길이
```

조건의 결과가 한 방향으로만 변하므로, 길이 1부터 모든 값을 확인하지 않고 이분 탐색으로 최대 가능 길이를 찾을 수 있다.

탐색 구간은 다음과 같이 설정했다.

- `left = 1`: 파의 길이는 양의 정수이므로 최소 후보는 1이다.
- `right = max(onions)`: 가장 긴 원본 파보다 긴 조각은 만들 수 없다.
- `mid = (left + right) // 2`: 현재 확인할 파 조각의 길이다.

`mid` 길이의 조각을 `C`개 이상 만들 수 있으면 더 긴 길이를 확인하고, 만들 수 없으면 길이를 줄인다. 반복문 종료 후 `right`에는 `C`개 이상 만들 수 있는 최대 길이가 남는다.

최대 길이를 `right`라고 할 때 남은 파의 길이는 다음처럼 계산해야 한다.

```python
sum(onions) - right * C
```

만들 수 있는 조각 수가 `C`개보다 많더라도 실제 주문받은 파닭은 정확히 `C`개이므로, 사용한 파의 양은 `right × C`다.

## 사용한 자료구조

### 리스트(List)

입력받은 `S`개 파의 길이를 `onions` 리스트에 저장했다.

```python
onions = [int(input()) for _ in range(S)]
```

이분 탐색에서 후보 길이 `mid`가 바뀔 때마다 모든 파를 순회하며 만들 수 있는 조각 수를 계산한다. 파의 입력 순서는 결과에 영향을 주지 않으므로 별도의 정렬은 필요하지 않다.

파의 전체 길이도 마지막 답을 계산할 때 필요하므로 입력 후 `sum(onions)`로 구한다.

## 사용한 알고리즘

### 이분 탐색(Binary Search)

정렬된 배열에서 값을 찾는 대신, 정답이 될 수 있는 파 조각의 길이 범위를 절반씩 줄이는 데 이분 탐색을 사용했다.

### 매개변수 탐색(Parametric Search)

“한 마리에 넣을 수 있는 파의 최대 길이”를 바로 구하지 않고 다음 결정 문제로 바꾸었다.

> 길이가 `mid`인 파 조각을 `C`개 이상 만들 수 있는가?

결정 함수가 참이면 `mid`는 가능한 길이이므로 더 큰 값을 탐색한다. 거짓이면 `mid`가 너무 길다는 뜻이므로 더 작은 값을 탐색한다.

```python
if count >= C:
    left = mid + 1
else:
    right = mid - 1
```

이 과정을 반복하면 가능한 길이와 불가능한 길이의 경계를 찾을 수 있다.

## 시간복잡도

가장 긴 파의 길이를 `L`이라고 하자.

- 한 번의 가능 여부 확인: 파 `S`개를 순회하므로 `O(S)`
- 이분 탐색 횟수: 길이 범위를 절반씩 줄이므로 `O(log L)`
- 전체 파 길이 계산: `O(S)`
- 전체 시간복잡도: **`O(S log L)`**
- 공간복잡도: 파 길이 `S`개를 저장하므로 **`O(S)`**

파의 길이가 최대 `10^9`이어도 이분 탐색은 약 30번만 수행되므로, 최대 `S`개의 파를 매번 확인해도 완전 탐색보다 훨씬 효율적이다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[S개의 파 길이 입력]
          |
          v
[전체 길이 total 계산]
          |
          v
[탐색 범위: left = 1, right = max(onions)]
          |
          v
[mid 길이로 만들 수 있는 조각 수 계산]
          |
          v
     count >= C 인가?
       /             \
     Yes             No
      |                |
      v                v
[더 길게 탐색]     [더 짧게 탐색]
 left = mid + 1     right = mid - 1
       \              /
        v            v
    [left <= right 동안 반복]
               |
               v
 [right = C개를 만들 수 있는 최대 길이]
               |
               v
[남은 파 = total - right × C]
```

## 최종 제출 코드

```python
import sys

input = sys.stdin.readline

S, C = map(int, input().split())
onions = [int(input()) for _ in range(S)]

total = sum(onions)
left = 1
right = max(onions)

while left <= right:
    mid = (left + right) // 2
    count = 0

    for onion in onions:
        count += onion // mid

    if count >= C:
        left = mid + 1
    else:
        right = mid - 1

print(total - right * C)
```

## 오늘의 회고(실수한 점 포함)

처음 코드에서 파 조각의 길이를 탐색 대상으로 두고, `p // mid`를 모두 더해 파닭을 몇 개 만들 수 있는지 판단한 방향은 맞았다. 자를 길이가 증가할수록 만들 수 있는 개수가 감소한다는 단조성을 이용한 매개변수 탐색이다.

다만 다음 부분은 수정해야 한다.

1. **`left = 0`으로 시작한 점**

   자를 길이는 양의 정수여야 한다. 탐색 후보에 0을 포함하면 조건에 따라 `p // mid`에서 0으로 나누는 오류가 발생할 수 있으므로 `left = 1`로 시작해야 한다.

2. **`while left < right`와 경계 이동 방식을 함께 사용한 점**

   `left = mid + 1`, `right = mid - 1` 방식은 `while left <= right`와 함께 사용해야 모든 후보를 빠짐없이 검사할 수 있다. 반복이 끝나면 `right`가 마지막으로 가능했던 길이라는 불변식도 명확해진다.

3. **반복문 안에서 계산한 마지막 `answer`를 출력한 점**

   마지막으로 검사한 `mid`가 최대 가능 길이라는 보장은 없다. 따라서 이분 탐색이 끝난 뒤 확정된 최대 길이 `right`를 기준으로 답을 계산해야 한다.

4. **`sum(p % mid)`를 남은 파라고 계산한 점**

   나머지만 더하면 만들 수 있었지만 사용하지 않은 완전한 파 조각을 놓친다.

   예를 들어 길이 10인 파가 2개 있고 파닭을 3개 주문받았다고 하자.

   ```text
   최대 조각 길이 = 5
   만들 수 있는 조각 = 10 // 5 + 10 // 5 = 4개
   실제 사용하는 조각 = 3개
   ```

   `10 % 5 + 10 % 5`는 0이지만, 네 번째 5cm 조각은 사용하지 않았으므로 실제 남은 파는 5cm다.

   ```text
   전체 파 길이 - 실제 사용량
   = 20 - (5 × 3)
   = 5
   ```

예제에서는 최대 길이로 정확히 `C`개의 조각이 만들어져 나머지 합도 우연히 정답이 된다. 하지만 항상 정확히 `C`개가 만들어지는 것은 아니므로, 답은 반드시 `전체 길이 - 최대 조각 길이 × C`로 계산해야 한다.

이번 문제를 통해 이분 탐색에서는 단순히 범위를 줄이는 것뿐만 아니라 **반복 종료 후 어느 변수가 마지막 가능 값을 가리키는지** 명확하게 설계해야 한다는 점을 복기했다. 또한 문제에서 요구하는 최종 값이 탐색 대상 자체인지, 탐색 결과로 다시 계산해야 하는 값인지 구분해야 한다.
