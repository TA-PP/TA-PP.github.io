## 문제 정의

[백준 2109번 순회강연](https://www.acmicpc.net/problem/2109)은 여러 대학에서 제안한 강연 중 일부를 선택해 얻을 수 있는 최대 강연료를 구하는 문제다.

각 강연 정보는 다음 두 값으로 주어진다.

- `p`: 해당 강연을 했을 때 받는 강연료
- `d`: 강연을 진행할 수 있는 마감일

하루에는 하나의 대학에서만 강연할 수 있고, 어떤 강연을 선택했다면 `d`일 안에 진행해야 한다. 모든 강연을 할 필요는 없으므로 마감일을 지키면서 강연료 합이 최대가 되도록 강연을 선택해야 한다.

예를 들어 마감일이 2일인 강연들만 고려하고 있다면 실제로 선택할 수 있는 강연은 최대 2개다. 3개를 후보로 넣었다면 그중 강연료가 가장 적은 강연을 포기하는 것이 유리하다.

## 접근 및 설계

처음 작성한 코드에서는 강연을 정렬한 뒤 힙에 하나씩 넣고, 선택한 강연 수가 어떤 기준을 넘으면 가장 작은 원소를 제거하려고 했다.

```python
for _ in range(N):
    d, p = map(int, input().split())
    lectures.append((d, p))

lectures.sort()

for lecture in lectures:
    heapq.heappush(heap, lecture)

    if len(heap) > lecture[0]:
        heapq.heappop(heap)
```

“후보를 힙에 넣고 일정에 넣을 수 없는 강연이 생기면 하나를 제거한다”는 방향은 이 문제의 정답 그리디와 가깝다. 다만 튜플의 각 위치가 무엇을 의미하는지 정리되지 않아 실제 연산 기준이 달라졌다.

### 1. 입력값의 순서를 반대로 해석했다

문제 입력은 `강연료 p`, `마감일 d` 순서다. 하지만 코드에서는 이를 `d, p`라는 변수로 받았다.

```python
d, p = map(int, input().split())
```

따라서 코드의 `d`에는 실제로 강연료가, `p`에는 마감일이 저장된다. 이후 `lecture[0]`을 마감일처럼 사용했지만 실제 값은 강연료다.

변수 이름부터 문제의 의미와 맞추면 실수를 줄일 수 있다.

```python
pay, deadline = map(int, input().split())
```

### 2. 강연료가 아니라 마감일을 기준으로 정렬해야 한다

기존의 `(d, p)`는 실제로 `(강연료, 마감일)`이므로 기본 정렬을 적용하면 강연료가 낮은 순서로 정렬된다.

이 알고리즘에서 “현재까지 고려한 강연은 모두 오늘 마감일까지 처리해야 한다”는 상태를 만들려면 마감일이 빠른 강연부터 확인해야 한다.

```python
lectures.append((deadline, pay))
lectures.sort()
```

### 3. 힙에는 강연료만 저장한다

기존 코드는 `(강연료, 마감일)` 튜플 전체를 힙에 넣었다. Python의 튜플은 첫 번째 값부터 비교하므로 이 경우에도 강연료가 작은 원소가 먼저 나오기는 한다. 하지만 입력 의미가 뒤바뀐 상태에서는 정렬 기준과 제한 조건을 함께 잘못 사용하게 된다.

최종 코드에서는 힙의 역할을 “현재까지 선택한 강연료 중 최솟값을 찾는 것”으로 제한하고 강연료만 저장한다.

```python
heapq.heappush(selected_pays, pay)
```

실제로 문제의 예제 입력을 기존 코드에 넣으면 강연료가 아니라 두 번째 값인 마감일들을 합산해 `39`를 출력한다. 올바른 최대 강연료는 `185`다. 이 차이를 통해 입력값의 의미가 정렬, 힙 비교, 최종 합산까지 연쇄적으로 영향을 준다는 것을 확인할 수 있다.

### 4. 선택 개수가 마감일을 초과하면 가장 싼 강연을 제거한다

마감일이 `deadline`인 강연까지 확인했을 때, 선택한 강연 수는 `deadline`개를 넘을 수 없다.

```python
if len(selected_pays) > deadline:
    heapq.heappop(selected_pays)
```

강연 하나를 반드시 포기해야 한다면 지금까지 선택한 강연 중 강연료가 가장 낮은 것을 제거해야 나머지 강연료 합이 최대가 된다. 최소 힙을 사용하면 이 값을 `O(log N)`에 제거할 수 있다.

## 사용한 자료구조

### 리스트(List)

모든 강연을 `(마감일, 강연료)` 튜플로 저장한다.

```python
lectures.append((deadline, pay))
```

마감일이 빠른 순서로 강연을 처리하기 위해 전체 목록을 정렬해야 하므로 `N`개의 강연 정보를 리스트에 보관한다.

튜플의 첫 번째 값을 `deadline`으로 두면 Python의 기본 튜플 정렬만으로 마감일 오름차순을 만들 수 있다.

```python
lectures.sort()
```

### 최소 힙(Min Heap)

`selected_pays`에는 현재까지 선택한 강연들의 강연료만 저장한다.

```python
heapq.heappush(selected_pays, pay)
```

Python의 `heapq`는 가장 작은 값이 루트에 위치하는 최소 힙이다. 일정에 포함할 수 있는 개수를 초과하면 `heapq.heappop()`으로 가장 싼 강연을 제거한다.

```python
heapq.heappop(selected_pays)
```

힙 내부가 전체 오름차순으로 정렬되는 것은 아니지만, 이 문제에서는 최솟값만 빠르게 제거하면 되므로 전체 정렬 상태가 필요하지 않다.

## 사용한 알고리즘

### 정렬(Sorting)

강연을 마감일 오름차순으로 정렬한다.

```python
lectures.sort()
```

이렇게 하면 현재 `(deadline, pay)`를 확인하는 시점에 힙에는 마감일이 현재 마감일보다 빠르거나 같은 강연의 후보만 들어 있다.

마감일이 같은 강연끼리는 강연료 순서가 달라도 최종 결과에 영향을 주지 않는다. 같은 마감일의 강연을 모두 넣는 동안 제한을 초과할 때마다 가장 작은 강연료를 제거하기 때문이다.

### 그리디(Greedy)

각 강연을 일단 선택 후보에 포함한 뒤, 현재 마감일까지 배치할 수 있는 강연 수보다 후보가 많아지면 가장 싼 강연을 제거한다.

```text
현재 마감일: 2일
힙의 강연료: [10, 50, 100]
선택한 강연 수: 3개

2일까지 가능한 강연은 최대 2개
-> 가장 싼 10을 제거
-> 50과 100을 유지
```

어떤 단계에서 후보가 마감일보다 하나 많다면 그중 하나는 반드시 제외해야 한다. 가장 싼 강연이 아닌 다른 강연을 제외한 해가 있다면, 그 강연을 가장 싼 강연과 바꿔도 마감일 가능 여부는 변하지 않고 총 강연료는 더 커지거나 같아진다.

따라서 매 단계에서 최저 강연료를 제거하는 선택은 최적해를 해치지 않는다.

## 시간복잡도

- 강연 `N`개 입력 및 저장: `O(N)`
- 마감일 기준 정렬: `O(N log N)`
- 각 강연의 힙 삽입: 최대 `O(log N)`
- 필요한 경우 힙 최솟값 제거: 최대 `O(log N)`
- 힙에 남은 강연료 합산: `O(N)`
- 전체 시간복잡도: **`O(N log N)`**
- 공간복잡도: **`O(N)`**

정렬과 힙 연산이 전체 시간복잡도를 결정한다.

## 최종 제출 코드

```python
import sys
import heapq

input = sys.stdin.readline

N = int(input())
lectures = []

for _ in range(N):
    pay, deadline = map(int, input().split())
    lectures.append((deadline, pay))

lectures.sort()

selected_pays = []

for deadline, pay in lectures:
    heapq.heappush(selected_pays, pay)

    if len(selected_pays) > deadline:
        heapq.heappop(selected_pays)

print(sum(selected_pays))
```

## 오늘의 회고(실수한 점 포함)

힙에 강연을 추가하고 일정에 넣을 수 있는 개수를 초과하면 가장 작은 값을 제거하려고 한 발상은 이 문제의 핵심에 가까웠다. 특히 모든 일정을 직접 배치하지 않고 선택할 강연료 후보만 유지하려는 방향이 좋았다.

다만 다음 부분을 반드시 수정해야 했다.

1. **입력 순서와 변수 이름이 반대였다.**

   문제는 `p d`, 즉 강연료와 마감일 순서로 값을 준다. 이를 `d, p`로 받으면서 이후 모든 인덱스의 의미가 뒤바뀌었다. 입력을 받은 직후부터 `pay`, `deadline`처럼 문제에서 맡은 역할이 드러나는 이름을 사용해야 한다.

2. **강연료 기준으로 정렬했다.**

   기존 튜플의 첫 값은 실제 강연료였기 때문에 `lectures.sort()`가 마감일이 아닌 강연료 순서로 동작했다. 이 문제의 그리디 상태를 만들기 위해서는 반드시 마감일이 빠른 강연부터 처리해야 한다.

3. **힙 크기를 강연료와 비교했다.**

   `len(heap) > lecture[0]`에서 `lecture[0]`은 실제로 강연료였다. 선택한 강연 개수와 비교해야 하는 값은 강연료가 아니라 현재 강연의 마감일이다.

4. **힙에 필요한 값보다 많은 정보를 저장했다.**

   힙의 목적은 포기할 최저 강연료를 찾는 것이다. 강연 전체 튜플을 넣기보다 강연료만 넣으면 자료구조의 역할과 비교 기준이 명확해진다.

5. **들여쓰기와 변수 표현을 정리할 필요가 있었다.**

   `heappop()`과 합산 부분의 들여쓰기가 일정하지 않았고, 마지막 합계도 반복문 대신 `sum(selected_pays)`로 의도를 간단히 표현할 수 있다.

이번 문제를 통해 마감일이 있는 작업 중 이익을 최대화하는 문제에서는 **마감일순으로 작업을 확인하면서, 현재까지 선택한 이익을 최소 힙에 유지하고, 가능한 작업 수를 초과하면 최솟값을 제거하는 전략**을 복기했다. 또한 튜플을 정렬이나 힙에 사용할 때는 각 인덱스가 어떤 비교 기준이 되는지 먼저 적어 보는 습관이 중요하다는 점을 확인했다.
