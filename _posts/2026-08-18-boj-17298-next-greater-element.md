## 문제 정의

[백준 17298번 오큰수](https://www.acmicpc.net/problem/17298)는 수열의 각 원소에 대해 오른쪽에 있으면서 현재 값보다 큰 수 중 가장 왼쪽에 있는 값을 구하는 문제다.

현재 원소보다 큰 값이 오른쪽에 여러 개 있어도 가장 먼저 만나는 값이 오큰수다. 그런 값이 없다면 `-1`을 출력한다.

```text
수열:   3 5 2 7
오큰수: 5 7 7 -1
```

- `3`의 오른쪽에서 처음 만나는 큰 수는 `5`다.
- `5`의 오른쪽에서 처음 만나는 큰 수는 `7`이다.
- `2`의 오른쪽에서 처음 만나는 큰 수는 `7`이다.
- `7`의 오른쪽에는 더 큰 수가 없으므로 `-1`이다.

`N`은 최대 1,000,000이다. 각 원소마다 오른쪽을 다시 탐색하면 최악의 경우 `O(N²)`이 되어 시간 제한을 통과할 수 없다.

## 접근 및 설계

작성한 코드에서는 수열을 왼쪽부터 읽으면서 현재 값이 스택의 마지막 값보다 크면 스택을 꺼냈다.

```python
for num in numbers:
    while stack and num > stack[-1]:
        answer.append(num)
        stack.pop()
    stack.append(num)
```

이 `while`문의 발상은 정확하다. 스택에 남아 있는 이전 값보다 현재 값이 크다면 현재 값은 그 이전 값의 오른쪽에서 처음 만난 큰 수이므로 오큰수가 된다.

하지만 정답을 저장하는 방법 때문에 결과가 틀어질 수 있다.

### 1. 발견 순서와 원래 인덱스 순서는 다르다

현재 코드는 오큰수를 찾을 때마다 `answer.append(num)`으로 정답을 발견 순서대로 추가한다.

```python
answer.append(num)
```

그러나 스택은 후입선출 구조이므로 여러 원소가 한 번에 빠질 때 원래 수열의 뒤쪽 원소부터 처리된다. 오큰수의 출력 순서는 반드시 원래 수열의 인덱스 순서여야 한다.

다음 반례를 보자.

```text
수열: 4 1 2 3
```

처리 과정은 다음과 같다.

```text
4 추가 -> stack = [4]
1 추가 -> stack = [4, 1]
2 입력 -> 1의 오큰수는 2, answer에 2 추가
3 입력 -> 2의 오큰수는 3, answer에 3 추가
종료
```

현재 코드는 마지막에 `-1`을 한 번만 추가해 `[2, 3, -1]`을 만든다. 하지만 실제 정답은 다음과 같다.

```text
4의 오큰수: -1
1의 오큰수: 2
2의 오큰수: 3
3의 오큰수: -1

정답: -1 2 3 -1
```

각 오큰수가 어느 원소의 정답인지 기록하려면 스택에 값만 저장할 것이 아니라 **원소의 인덱스**를 저장해야 한다.

### 2. 정답 배열을 `-1`로 미리 채운다

오큰수를 찾지 못한 원소는 모두 `-1`이어야 한다. 현재 코드는 반복문이 끝난 뒤 `answer.append(-1)`을 한 번만 실행한다.

```python
answer.append(-1)
```

하지만 해결되지 않은 원소는 여러 개일 수 있다. 예를 들어 내림차순 수열 `5 4 3 2 1`은 모든 원소의 오큰수가 `-1`이다.

정답 배열을 처음부터 `-1`로 초기화하면 오큰수를 찾은 위치만 갱신하고, 끝까지 스택에 남은 인덱스는 별도로 처리하지 않아도 된다.

```python
answer = [-1] * N
```

### 3. 스택에 값 대신 인덱스를 저장한다

현재 인덱스를 `i`라고 할 때 스택의 마지막 인덱스가 가리키는 값과 현재 값을 비교한다.

```python
while stack and numbers[stack[-1]] < numbers[i]:
    index = stack.pop()
    answer[index] = numbers[i]
```

스택에서 꺼낸 `index`는 아직 오큰수를 찾지 못한 이전 원소의 위치다. 현재 값은 그 원소보다 크고, 왼쪽부터 순서대로 탐색하면서 처음 만난 큰 값이므로 해당 위치의 오큰수가 된다.

### 4. 리스트 자체가 아니라 원소를 공백으로 출력한다

```python
print(answer)
```

이 코드는 Python 리스트 표현인 대괄호와 쉼표까지 출력한다.

```text
[-1, 2, 3, -1]
```

문제에서 요구하는 형식은 공백으로 구분된 숫자다.

```text
-1 2 3 -1
```

`N`이 크므로 최종 코드에서는 문자열로 합쳐 한 번에 출력한다.

```python
sys.stdout.write(' '.join(map(str, answer)))
```

## 사용한 자료구조

### 리스트(List)

입력 수열을 `numbers` 리스트에 저장한다.

```python
numbers = list(map(int, input().split()))
```

스택에는 인덱스를 저장하므로 `numbers[index]`로 해당 위치의 실제 값을 확인할 수 있다.

정답도 입력과 같은 길이의 리스트로 관리한다.

```python
answer = [-1] * N
```

오큰수를 찾은 인덱스만 현재 값으로 덮어쓰고, 찾지 못한 인덱스는 초기값 `-1`을 유지한다.

### 단조 스택(Monotonic Stack)

스택에는 아직 오큰수를 찾지 못한 원소의 인덱스를 저장한다.

```python
stack.append(i)
```

스택이 가리키는 값들은 아래에서 위로 갈수록 단조 감소하거나 같은 상태를 유지한다.

```text
numbers[stack[0]] >= numbers[stack[1]] >= ... >= numbers[stack[-1]]
```

현재 값보다 작은 값들은 모두 스택에서 제거되기 때문이다. 같은 값은 오큰수가 될 수 없다. 오큰수는 현재 값보다 **엄격하게 큰 수**여야 하므로 비교 조건에 `<`를 사용하고 같은 값은 스택에 남긴다.

## 사용한 알고리즘

### 단조 스택을 이용한 오큰수 탐색

수열을 왼쪽부터 한 번 순회한다.

1. 스택이 비어 있지 않은지 확인한다.
2. 스택의 마지막 인덱스가 가리키는 값이 현재 값보다 작은지 확인한다.
3. 작다면 해당 인덱스를 꺼내 정답을 현재 값으로 갱신한다.
4. 더 이상 작은 값이 없을 때까지 반복한다.
5. 현재 인덱스를 스택에 추가한다.

```python
for i in range(N):
    while stack and numbers[stack[-1]] < numbers[i]:
        answer[stack.pop()] = numbers[i]

    stack.append(i)
```

현재 값이 어떤 이전 원소보다 크다면, 현재 값은 그 원소의 오른쪽에서 처음 발견한 큰 수다. 이전 인덱스는 지금까지 스택에 남아 있었으므로 현재 위치 전에 더 큰 수를 만나지 못했다는 뜻이다.

### 왜 각 원소를 한 번만 처리하는가

각 인덱스는 스택에 정확히 한 번 들어간다. 오큰수를 찾으면 한 번 빠지고, 찾지 못하면 끝까지 남는다. 한 번 제거된 인덱스는 다시 스택에 들어가지 않는다.

따라서 `while`문이 `for`문 안에 있어도 전체 `pop()` 횟수는 최대 `N`번이다. 각 위치에서 오른쪽을 다시 탐색하는 것이 아니라, 아직 해결되지 않은 후보만 스택에 유지한다.

## 시간복잡도

- 입력 수열 저장: `O(N)`
- 각 인덱스를 스택에 한 번 추가: `O(N)`
- 각 인덱스를 스택에서 최대 한 번 제거: `O(N)`
- 결과 문자열 생성 및 출력: `O(N)`
- 전체 시간복잡도: **`O(N)`**
- 공간복잡도: **`O(N)`**

최악의 경우 내림차순 수열에서는 모든 인덱스가 스택에 남으므로 스택 공간은 `O(N)`이다.

중첩 반복문 형태만 보면 `O(N²)`처럼 보일 수 있지만, 각 인덱스의 `push`와 `pop`이 최대 한 번씩이라는 점을 기준으로 계산하면 전체는 `O(N)`이다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[answer를 N개의 -1로 초기화]
              |
              v
       [현재 인덱스 i 확인]
              |
              v
         [스택이 비었는가?]
          /             \
        Yes             No
         |               |
         |               v
         |   [numbers[stack[-1]] < numbers[i]?]
         |             /              \
         |           Yes              No
         |            |                |
         |            v                |
         |      [이전 인덱스 pop]       |
         |      [answer[index] 갱신]    |
         |            |                |
         |      [조건 다시 확인]        |
         |            \               /
         |             v             v
         +------> [현재 인덱스를 push]
                         |
                         v
                 [다음 인덱스 확인]
                         |
                         v
                [모든 원소 처리 완료]
                         |
                         v
           [answer를 공백으로 연결해 출력]
```

## 최종 제출 코드

```python
import sys

input = sys.stdin.buffer.readline

N = int(input())
numbers = list(map(int, input().split()))

answer = [-1] * N
stack = []

for i in range(N):
    while stack and numbers[stack[-1]] < numbers[i]:
        answer[stack.pop()] = numbers[i]

    stack.append(i)

sys.stdout.write(' '.join(map(str, answer)))
```

로컬 테스트를 위해 사용한 아래 코드는 백준 제출 시 제거해야 한다.


## 오늘의 회고(실수한 점 포함)

현재 값이 스택의 마지막 값보다 크면 이전 값들의 오큰수가 된다는 핵심 발상은 잘 잡았다. 오른쪽을 매번 다시 확인하지 않고 아직 오큰수를 찾지 못한 값만 스택에 남기는 방향이 단조 스택 풀이의 출발점이다.

다만 값만 저장하면서 정답 위치에 대한 정보가 사라진 것이 가장 큰 문제였다.

이번 풀이에서 수정한 부분은 다음과 같다.

1. **정답을 발견 순서대로 추가했다.**

   스택은 나중에 들어간 원소가 먼저 나오므로 오큰수를 발견하는 순서는 원래 인덱스 순서와 다를 수 있다. 결과가 어느 원소의 정답인지 기록하려면 인덱스가 필요하다.

2. **스택에 값만 저장했다.**

   값만 알면 비교는 할 수 있지만 `answer`의 어느 위치를 갱신해야 하는지 알 수 없다. 스택에 인덱스를 저장하면 비교와 정답 기록을 모두 처리할 수 있다.

3. **해결되지 않은 원소가 하나뿐이라고 가정했다.**

   반복문이 끝난 뒤 스택에 여러 인덱스가 남을 수 있다. 정답 배열을 `-1`로 초기화하면 이들을 별도로 꺼내지 않아도 된다.

4. **출력 형식을 확인하지 않았다.**

   `print(answer)`는 리스트 표현을 출력한다. 코딩 테스트에서는 알고리즘 결과뿐 아니라 공백, 줄바꿈, 괄호 같은 출력 형식도 정답의 일부다.

5. **같은 값은 오큰수가 아니다.**

   비교 조건은 `<=`가 아니라 `<`여야 한다. 현재 값과 같은 이전 값은 오큰수를 찾은 것이 아니므로 스택에 계속 남겨야 한다.

이번 문제를 통해 각 원소의 오른쪽에서 처음 만나는 큰 값이나 작은 값을 찾는 문제에서는 **아직 답을 찾지 못한 인덱스를 단조 스택에 저장하는 방식**을 우선 검토해야 한다는 점을 복기했다. 또한 결과가 입력 순서대로 필요하다면 값만 보관하지 말고 원래 위치를 함께 추적해야 한다.
