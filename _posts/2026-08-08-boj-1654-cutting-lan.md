## 문제 정의

길이가 서로 다른 `K`개의 랜선을 같은 길이로 잘라서 최소 `N`개를 만들어야 한다.
이때 만들 수 있는 **랜선의 최대 길이**를 구하는 문제다.

랜선을 이어 붙일 수는 없고, 각 랜선에서 잘라 낸 나머지 길이는 버린다.
따라서 어떤 길이 `L`로 잘랐을 때 만들 수 있는 랜선의 개수는 다음과 같다.

```text
(첫 번째 랜선 길이 // L) + ... + (K번째 랜선 길이 // L)
```

단순히 모든 길이를 하나씩 확인하면 최대 랜선 길이가 약 21억이므로 시간 안에 해결하기 어렵다.

## 접근 및 설계

처음에는 자를 길이를 정하고, 각 랜선에서 몇 개가 나오는지 모두 더하는 방식으로 접근했다.
여기서 중요한 점은 **자를 길이가 짧아질수록 만들 수 있는 랜선 개수는 많아지고, 길어질수록 개수는 적어진다**는 것이다.

예를 들어 자를 길이에 따른 결과는 다음처럼 한 방향으로만 변한다.

```text
자를 길이:       짧음 ----------------------------> 길어짐
N개 이상 생성:   가능 가능 가능 가능 | 불가능 불가능 불가능
                                  ↑
                             찾아야 할 경계
```

이처럼 조건의 결과가 단조롭게 변하므로 모든 길이를 확인하지 않고 이분 탐색으로 가능한 최대 길이를 찾을 수 있다.

탐색 구간은 다음과 같이 잡았다.

- `left = 1`: 랜선 길이는 자연수이므로 최소 길이는 1이다.
- `right = max(lan)`: 가지고 있는 가장 긴 랜선보다 긴 랜선은 만들 수 없다.
- `mid = (left + right) // 2`: 현재 확인할 랜선 길이다.

`mid` 길이로 잘랐을 때 만든 랜선 수를 `count`라고 하면 다음과 같이 탐색 범위를 줄인다.

- `count >= N`: 현재 길이로 충분히 만들 수 있으므로, 더 긴 길이가 가능한지 오른쪽을 탐색한다.
- `count < N`: 필요한 개수를 만들 수 없으므로 길이를 줄이기 위해 왼쪽을 탐색한다.

반복문이 끝나면 `left`는 처음으로 불가능한 길이를 가리키고, `right`는 마지막으로 가능한 길이를 가리킨다. 따라서 정답은 `right`다.

## 사용한 자료구조

### 리스트(List)

입력으로 주어진 `K`개 랜선의 길이를 `lan` 리스트에 저장했다.

```python
lan = [int(input()) for _ in range(K)]
```

이분 탐색에서 후보 길이 `mid`가 바뀔 때마다 모든 랜선을 순회하며 만들 수 있는 개수를 다시 계산해야 한다. 랜선 길이의 순서는 결과에 영향을 주지 않으므로 별도의 정렬이나 복잡한 자료구조는 필요하지 않다.

## 사용한 알고리즘

### 이분 탐색(Binary Search)

일반적인 이분 탐색은 정렬된 배열에서 특정 값을 찾지만, 이 문제에서는 **정답이 존재할 수 있는 길이 범위**를 절반씩 줄이는 데 사용했다.

### 매개변수 탐색(Parametric Search)

최댓값을 바로 계산하는 대신 다음 결정 문제로 바꾸었다.

> 랜선을 길이 `mid`로 잘랐을 때 `N`개 이상 만들 수 있는가?

결정 함수는 아래와 같다.

```python
count = sum(length // mid for length in lan)
```

결과가 참이면 더 큰 길이에 도전하고, 거짓이면 더 짧은 길이를 확인한다. 결국 `N`개 이상 만들 수 있는 길이 중 최댓값을 찾는다.

## 시간복잡도

가장 긴 랜선의 길이를 `M`이라고 하자.

- 한 번의 가능 여부 확인: 랜선 `K`개를 순회하므로 `O(K)`
- 이분 탐색 횟수: 길이 범위를 절반씩 줄이므로 `O(log M)`
- 전체 시간복잡도: **`O(K log M)`**
- 공간복잡도: 랜선 길이 `K`개를 저장하므로 **`O(K)`**

`M`이 최대 `2^31 - 1`이어도 이분 탐색은 약 31번만 수행되므로 충분히 빠르다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[K개의 랜선 길이 입력]
          |
          v
[탐색 범위: left = 1, right = max(lan)]
          |
          v
[mid 길이로 만들 수 있는 랜선 수 계산]
          |
          v
    count >= N 인가?
       /          \
     Yes          No
      |             |
      v             v
[더 길게 탐색]  [더 짧게 탐색]
 left = mid + 1  right = mid - 1
       \           /
        v         v
   [left <= right 동안 반복]
              |
              v
 [마지막으로 가능했던 길이 right 출력]
```

## 최종 제출 코드

```python
import sys

input = sys.stdin.readline

K, N = map(int, input().split())
lan = [int(input()) for _ in range(K)]

left = 1
right = max(lan)

while left <= right:
    mid = (left + right) // 2
    count = 0

    for length in lan:
        count += length // mid

    if count >= N:
        left = mid + 1
    else:
        right = mid - 1

print(right)
```

로컬 테스트를 위해 사용한 아래 코드는 백준 제출 시 제거해야 한다.

```python

```

## 오늘의 회고(실수한 점 포함)

처음 작성한 코드의 큰 방향은 맞았다. 랜선 길이를 답의 후보로 두고, `mid` 길이로 몇 개를 만들 수 있는지 계산한 뒤 탐색 범위를 절반씩 줄였다. 별도의 정렬이 필요하지 않다는 점도 잘 판단했다.

다만 다음 두 부분은 반드시 수정해야 한다.

1. **`left = 0`으로 시작한 점**

   랜선 길이는 0이 될 수 없다. 탐색 과정에서 `mid`가 0이 되면 `i // mid`에서 `ZeroDivisionError`가 발생할 수 있으므로 최소 후보 길이는 1로 잡아야 한다.

2. **반복문 종료 후 `mid`를 출력한 점**

   마지막으로 계산한 `mid`가 항상 최대 가능 길이라는 보장은 없다. 반복 종료 시 `right`가 조건을 만족하는 최대 길이이므로 `print(right)`를 사용해야 한다.

   예를 들어 길이가 1인 랜선 하나로 1개를 만드는 경우 정답은 1이다. 하지만 기존 탐색 범위에서 마지막으로 검사한 값이 2가 될 수 있어 `mid`를 출력하면 오답이 된다. 종료 시점의 경계를 직접 확인하면 다음과 같다.

   ```text
   right = 1  # 만들 수 있는 최대 길이
   left  = 2  # 처음으로 만들 수 없는 길이
   mid   = 2  # 마지막 검사값일 뿐, 정답을 보장하지 않음
   ```

추가로 상한을 `2^31 - 1`로 두어도 이분 탐색은 동작하지만, 입력받은 랜선 중 최댓값인 `max(lan)`을 사용하면 실제로 가능한 범위만 탐색하므로 의도가 더 분명하다.

이번 문제를 통해 최댓값·최솟값을 요구하는 문제에서 답을 직접 구하기 어렵다면, 먼저 **“이 값이 가능한가?”라는 결정 문제로 바꿀 수 있는지** 확인해야 한다는 점을 복기했다. 그리고 이 결정 결과가 한 방향으로 변한다면 이분 탐색을 적용할 수 있다.
