## 문제 정의

[백준 1806번 부분합](https://www.acmicpc.net/problem/1806)은 자연수로 이루어진 수열에서 합이 `S` 이상인 연속 부분 수열 중 길이가 가장 짧은 구간을 찾는 문제다.

```text
수열: 5 1 3 5 10 7 4 9 2 8
S = 15
```

`[5, 10]`, `[10, 7]`처럼 합이 15 이상인 길이 2의 연속 구간이 존재하므로 정답은 2다.

문제에서 요구하는 조건은 다음 두 가지다.

1. 선택한 원소들이 원래 수열에서 연속해야 한다.
2. 부분합이 `S`와 같을 필요는 없으며 `S` 이상이면 된다.

주요 제한은 다음과 같다.

- `10 <= N < 100,000`
- `0 < S <= 100,000,000`
- 각 원소는 10,000 이하의 자연수다.
- 조건을 만족하는 구간이 없다면 0을 출력한다.

`N`이 최대 약 100,000이므로 모든 시작점과 끝점을 이중 반복문으로 확인하는 `O(N²)` 풀이는 사용할 수 없다.

## 접근 및 설계

이번 문제는 여러 번 코드를 수정하며 정렬 기반 투 포인터에서 연속 구간 슬라이딩 윈도우로 접근을 바꿨다.

### 1차 시도: 정렬 후 양 끝의 두 수 비교

처음에는 수열을 정렬하고 양 끝 값의 합을 비교했다.

```python
numbers.sort()

left = 0
right = N - 1

while left < right:
    temp = numbers[left] + numbers[right]
```

이 방식은 백준 3273번처럼 두 원소의 합을 찾는 문제에는 사용할 수 있지만, 이번 문제에는 적용할 수 없다.

첫째, 문제는 임의의 두 수가 아니라 **연속된 여러 수의 합**을 요구한다. 둘째, 정렬하면 원래 수열의 순서가 바뀌어 어떤 원소들이 연속했는지 알 수 없게 된다.

```text
원래 수열: [5, 1, 3, 5, 10]
정렬 수열: [1, 3, 5, 5, 10]
```

정렬된 배열의 `[5, 10]`이 붙어 있더라도 원래 배열에서 같은 위치 관계였다고 보장할 수 없다. 연속 부분 수열 문제에서는 입력 순서를 보존해야 한다.

또한 첫 코드는 합이 정확히 `S`인 두 수의 개수를 세고 있었지만, 문제에서 요구하는 것은 합이 `S` 이상인 연속 구간의 **최소 길이**다.

### 2차 시도: 연속 구간을 직접 더하기

두 번째 코드에서는 정렬을 제거하고 `[left, right]` 범위를 직접 더했다.

```python
temp = 0
for i in range(left, right + 1):
    temp += numbers[i]
```

연속 구간을 확인한다는 점은 올바르게 바뀌었다. 하지만 포인터가 움직일 때마다 구간 전체를 다시 더하므로 한 번의 합 계산에 `O(N)`이 걸리고, 전체 시간복잡도는 최악의 경우 `O(N²)`이 된다.

또한 다음 조건 때문에 합이 `S`보다 큰 유효 구간은 정답 후보에 포함되지 않았다.

```python
if temp == S:
    answer.append(right - left + 1)
```

문제의 조건은 `temp == S`가 아니라 `temp >= S`다.

### 3차 시도: 구간합을 변수에 유지

세 번째 코드에서는 `temp`에 현재 구간합을 저장하고 포인터가 움직인 원소만 더하거나 빼는 방식으로 개선했다.

```python
temp += numbers[right]
temp -= numbers[left]
```

이 변화가 슬라이딩 윈도우의 핵심이다. 매번 구간 전체를 다시 더하지 않으므로 합 갱신을 `O(1)`에 할 수 있다.

다만 `right`를 증가시킨 직후 범위를 확인하지 않고 접근했다.

```python
right += 1
temp += numbers[right]
```

`right`가 `N`이 되면 `numbers[N]`에 접근해 `IndexError`가 발생한다. `N = 1`일 때 `numbers[1]`로 초기화할 수 없는 문제도 있다.

### 4차 시도: 더하기 위치 변경

네 번째 코드에서는 반복문 시작마다 `numbers[right]`를 더했다.

```python
while left < N and right < N:
    temp += numbers[right]
```

하지만 `temp >= S`인 경우에는 `right`가 이동하지 않고 `left`만 이동한다. 다음 반복에서도 같은 `numbers[right]`를 다시 더하므로 오른쪽 끝 원소가 중복으로 합산된다.

슬라이딩 윈도우에서는 포인터가 실제로 이동하는 순간에만 해당 원소를 더하거나 빼야 한다.

이 단계에서도 `temp == S`일 때만 길이를 저장해 `S`보다 큰 구간을 놓쳤다.

### 5차 시도: 확장과 축소 구조 완성

마지막 코드에서는 합이 작을 때 오른쪽을 확장하고, 합이 `S` 이상이면 왼쪽을 축소하는 구조를 만들었다.

```python
if temp < S:
    right += 1
    temp += numbers[right]
elif temp >= S:
    answer.append(right - left + 1)
    temp -= numbers[left]
    left += 1
```

합이 `S`보다 커도 후보 길이를 저장하도록 바뀌었고, 구간합을 매번 다시 계산하지 않는 점도 맞다.

그러나 초기 상태가 서로 일치하지 않는다.

```python
right = 1
temp = numbers[0]
```

`right`는 인덱스 1을 가리키지만 `temp`에는 `numbers[0]`만 들어 있다. 첫 반복에서 `temp < S`이면 `right`를 먼저 2로 증가시킨 뒤 `numbers[2]`를 더하므로 `numbers[1]`을 건너뛴다.

```text
numbers = [5, 10, 1]
S = 15

실제 최소 구간: [5, 10], 길이 2
마지막 코드의 합: 5 -> 5 + 1
numbers[1]인 10을 더하지 않음
```

또한 조건을 만족하는 구간이 없으면 `answer`가 빈 리스트이므로 `min(answer)`에서 `ValueError`가 발생한다. 이 경우 문제에서 요구하는 출력은 0이다.

### 최종 설계: right를 for문으로 확장

오른쪽 포인터의 범위 처리와 합산 시점을 단순하게 만들기 위해 `for right in range(N)`을 사용한다.

```python
for right in range(N):
    current_sum += numbers[right]
```

오른쪽 원소는 반복마다 정확히 한 번 추가된다. 합이 `S` 이상이 되면 가능한 동안 왼쪽 원소를 빼며 구간을 축소한다.

```python
while current_sum >= S:
    answer = min(answer, right - left + 1)
    current_sum -= numbers[left]
    left += 1
```

이 구조에서는 각 원소가 오른쪽 포인터에 의해 한 번 더해지고, 왼쪽 포인터에 의해 최대 한 번 빠진다.

## 사용한 자료구조

### 리스트(List)

입력 순서 그대로 자연수 수열을 저장한다.

```python
numbers = list(map(int, input().split()))
```

연속 부분 수열 문제이므로 리스트를 정렬하지 않는다. 인덱스 `left`부터 `right`까지가 원래 수열에서 현재 확인 중인 연속 구간이다.

### 두 개의 인덱스 포인터

```python
left = 0

for right in range(N):
```

- `left`: 현재 윈도우의 시작 위치
- `right`: 현재 윈도우의 끝 위치

`right`는 구간을 확장하고 `left`는 구간을 축소한다. 두 포인터 모두 오른쪽으로만 이동한다.

### 현재 구간합 변수

```python
current_sum = 0
```

현재 `[left, right]` 구간의 합을 저장한다. 오른쪽 원소가 들어올 때 더하고 왼쪽 원소가 빠질 때 빼므로 구간 전체를 다시 순회하지 않는다.

### 최소 길이 변수

```python
answer = N + 1
```

유효한 구간 길이는 최대 `N`이므로 불가능한 값 `N + 1`을 초기값으로 사용한다. 탐색 후에도 값이 그대로라면 조건을 만족하는 구간이 없다는 뜻이므로 0을 출력한다.

후보 길이를 리스트에 모두 저장할 필요 없이 현재 최솟값 하나만 유지하면 추가 공간을 줄일 수 있다.

## 사용한 알고리즘

### 슬라이딩 윈도우

연속 구간의 양 끝을 이동하면서 합을 갱신하는 알고리즘이다.

```python
for right in range(N):
    current_sum += numbers[right]

    while current_sum >= S:
        answer = min(answer, right - left + 1)
        current_sum -= numbers[left]
        left += 1
```

수열의 모든 값이 자연수라는 조건이 중요하다.

- `right`를 이동해 자연수를 더하면 구간합은 증가한다.
- `left`를 이동해 자연수를 빼면 구간합은 감소한다.

합의 변화 방향을 예측할 수 있으므로 현재 합에 따라 어느 포인터를 움직일지 결정할 수 있다. 음수가 포함된 수열이라면 오른쪽을 확장했을 때 합이 항상 증가하지 않으므로 같은 방식이 성립하지 않는다.

### 왜 if가 아니라 while로 축소하는가

합이 `S` 이상인 구간을 찾았을 때 왼쪽 원소 하나만 빼고 다음 `right`로 넘어가면, 같은 오른쪽 끝을 가지는 더 짧은 유효 구간을 놓칠 수 있다.

```text
numbers = [1, 2, 10]
S = 10

[1, 2, 10]의 합 = 13, 길이 3
[2, 10]의 합    = 12, 길이 2
[10]의 합       = 10, 길이 1
```

따라서 `current_sum >= S`인 동안 계속 `left`를 이동하며 같은 `right`에서 만들 수 있는 모든 유효한 최소 구간을 확인해야 한다.

### 정렬하지 않는 이유

이 문제의 정답은 값들의 조합이 아니라 원래 수열에서 연속한 구간이다. 정렬은 원소의 위치 관계를 파괴한다.

문제에서 `연속`, `부분 수열`, `구간`이라는 표현이 나오면 정렬이 가능한 문제인지 먼저 확인해야 한다. 순서가 정답 조건에 포함된다면 정렬하면 안 된다.

### 예제 흐름

```text
numbers = [5, 1, 3, 5, 10, 7, 4, 9, 2, 8]
S = 15

right=0~3: 합 5 -> 6 -> 9 -> 14, 계속 확장
right=4:   합 24, 길이 5 후보
           left의 5 제거 -> 합 19, 길이 4 후보
           left의 1 제거 -> 합 18, 길이 3 후보
           left의 3 제거 -> 합 15, 길이 2 후보
           left의 5 제거 -> 합 10, 축소 종료

현재 최소 길이 = 2
```

이후에도 끝까지 탐색하지만 길이 1이면서 값이 `S` 이상인 원소는 없으므로 최종 정답은 2다.

## 시간복잡도

수열의 길이를 `N`이라고 하자.

- 오른쪽 포인터 이동: 최대 `N`번
- 왼쪽 포인터 이동: 최대 `N`번
- 전체 시간복잡도: **`O(N)`**
- 입력 리스트를 포함한 공간복잡도: **`O(N)`**
- 투 포인터 탐색의 추가 공간복잡도: **`O(1)`**

코드에 `for`문과 그 안의 `while`문이 있어 `O(N²)`처럼 보일 수 있다. 하지만 `left`는 전체 실행 동안 뒤로 돌아가지 않고 최대 `N`번만 증가한다. 두 포인터의 총 이동 횟수는 최대 `2N` 수준이므로 탐색은 `O(N)`이다.

2차 시도처럼 각 구간을 `for`문으로 다시 더하면 포인터 이동마다 `O(N)`이 추가되어 전체가 `O(N²)`이 된다. 현재 합을 변수로 유지하는 것이 시간복잡도를 줄이는 핵심이다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[N, S와 수열 입력]
          |
          v
[left = 0, sum = 0, answer = N + 1]
          |
          v
[right를 0부터 N-1까지 이동]
          |
          v
[numbers[right]를 current_sum에 추가]
          |
          v
   [current_sum >= S?]
       /          \
     Yes           No
      |             |
      v             |
[현재 구간 길이로    |
 answer 최솟값 갱신] |
      |             |
      v             |
[numbers[left] 제거] |
      |             |
      v             |
 [left 한 칸 이동]   |
      |             |
      +-- 합이 S 이상이면 반복
                    |
                    v
             [다음 right 확인]
                    |
                    v
            [모든 원소 확인 완료]
                    |
                    v
        [answer가 N + 1이면 0,
         아니면 answer 출력]
```

## 최종 제출 코드

```python
import sys

input = sys.stdin.readline

N, S = map(int, input().split())
numbers = list(map(int, input().split()))

left = 0
current_sum = 0
answer = N + 1

for right in range(N):
    current_sum += numbers[right]

    while current_sum >= S:
        answer = min(answer, right - left + 1)
        current_sum -= numbers[left]
        left += 1

if answer == N + 1:
    print(0)
else:
    print(answer)
```

로컬 테스트를 위해 사용한 다음 코드는 백준 제출 시 제거해야 한다.

```python
sys.stdin = open('./input/spatial_sum_input.txt', 'r')
```

파일명에서 사용한 `spatial_sum`보다는 문제 의미에 맞는 `partial_sum`이 더 자연스러운 이름이다.

## 오늘의 회고(실수한 점 포함)

처음에는 이전에 풀었던 두 수의 합 문제와 비슷하게 생각해 정렬 후 양 끝 포인터를 사용했다. 이후 연속 구간을 직접 더하는 방식, 구간합을 변수로 유지하는 방식으로 단계적으로 개선하면서 슬라이딩 윈도우의 형태에 가까워졌다.

1. **비슷한 알고리즘 문제라도 무엇을 선택하는지 먼저 구분해야 한다.**

   두 수의 합은 임의의 두 원소를 선택하지만, 부분합은 원래 순서를 유지한 연속 구간을 선택한다. 문제의 대상이 다르므로 같은 정렬 투 포인터를 그대로 사용할 수 없다.

2. **연속성이 조건이면 정렬을 조심해야 한다.**

   정렬하면 값 비교는 쉬워지지만 원래 인덱스 관계를 잃는다. 이번 문제에서 정렬은 정답 조건 자체를 훼손한다.

3. **`S 이상`과 `S와 같음`을 구분해야 한다.**

   여러 시도에서 `temp == S`일 때만 길이를 저장했다. 문제 문장의 비교 조건을 코드로 옮길 때 `==`, `>=`, `>`를 정확히 확인해야 한다.

4. **구간합은 전체를 다시 계산하지 않고 갱신할 수 있다.**

   `right`가 이동하면 새 원소를 더하고 `left`가 이동하면 기존 원소를 뺀다. 이 방식으로 구간 합산 비용을 `O(N²)`에서 `O(N)`으로 줄였다.

5. **포인터와 구간합이 같은 범위를 나타내야 한다.**

   마지막 시도에서는 `right = 1`이지만 `temp = numbers[0]`이라 상태가 일치하지 않았다. 포인터를 초기화할 때 현재 합이 어느 구간을 표현하는지 함께 적어보면 오프바이원 오류를 찾기 쉽다.

6. **배열 접근 전에 경계를 확인해야 한다.**

   `right += 1` 다음에 바로 `numbers[right]`를 사용하면 `right == N`일 때 오류가 발생한다. `for right in range(N)` 구조를 사용하면 범위 검사를 반복문이 보장해준다.

7. **조건을 만족하는 구간이 없을 때를 처리해야 한다.**

   후보 리스트가 비어 있으면 `min()`을 호출할 수 없다. 문제에서 요구한 대로 최솟값이 갱신되지 않았다면 0을 출력해야 한다.

8. **자연수라는 조건이 슬라이딩 윈도우를 가능하게 한다.**

   오른쪽을 확장하면 합이 증가하고 왼쪽을 축소하면 합이 감소한다. 입력값의 부호 조건이 알고리즘의 단조성을 보장한다는 점을 확인해야 한다.

이번 문제를 통해 투 포인터는 단순히 인덱스 두 개를 움직이는 기법이 아니라, **현재 구간을 명확하게 정의하고 포인터 이동에 맞춰 상태를 정확히 갱신하는 알고리즘**이라는 점을 복기했다. 코드가 거의 완성된 것처럼 보여도 작은 반례로 초기 구간과 첫 번째 이동을 직접 따라가 보는 습관이 필요하다.
