## 문제 정의

[백준 14729번 칠무해](https://www.acmicpc.net/problem/14729)는 `N`명의 학생 점수 중 가장 낮은 점수 7개를 오름차순으로 출력하는 문제다.

각 점수는 출력할 때 소수점 셋째 자리까지 표시해야 한다.

단순하게 생각하면 모든 점수를 리스트에 저장한 뒤 정렬하고 앞의 7개를 출력할 수 있다.

```python
scores.sort()
print(scores[:7])
```

하지만 `N`이 최대 1,000만이므로 모든 실수를 Python 리스트에 저장하면 메모리 사용량이 커진다. 실제로 필요한 값은 가장 낮은 7개뿐이므로 입력을 읽는 동안 후보 7개만 유지해야 한다.

## 접근 및 설계

처음 풀이에서도 전체 점수를 저장하지 않고 `score` 리스트의 크기를 최대 7로 유지하려고 했다.

```python
if len(score) == 7 and i < score[-1]:
    score.append(i)
    score.sort()
    score.pop(-1)
elif len(score) < 7:
    score.append(i)
```

핵심 발상은 맞다.

1. 점수가 7개보다 적으면 새 점수를 추가한다.
2. 이미 7개라면 현재 후보 중 가장 큰 점수와 새 점수를 비교한다.
3. 새 점수가 더 작으면 기존 최댓값을 제거하고 새 점수를 남긴다.

이 과정을 모든 입력에 적용하면 지금까지 읽은 점수 중 가장 낮은 7개만 남는다.

다만 현재 코드에는 `score[-1]`이 후보의 최댓값이라는 보장이 없다. 처음 7개를 넣는 동안 정렬하지 않았기 때문이다.

다음 입력을 생각해 보자.

```text
처음 7개: 1, 100, 2, 3, 4, 5, 6
다음 점수: 50
```

리스트의 마지막 값은 6이므로 `50 < score[-1]`은 거짓이다. 따라서 50을 버리게 된다. 하지만 후보 중 가장 큰 점수는 100이고, 실제로는 100을 버리고 50을 남겨야 한다.

```text
잘못 남은 후보: 1, 100, 2, 3, 4, 5, 6
올바른 후보:    1, 2, 3, 4, 5, 6, 50
```

처음 7개를 정렬한 뒤 계속 정렬 상태를 유지하면 기존 리스트 풀이도 고칠 수 있다. 이번에는 “후보 7개 중 최댓값을 반복해서 확인한다”는 동작에 더 잘 맞는 최대 힙으로 구현했다.

Python의 `heapq`는 최소 힙만 제공하므로 점수에 음수를 붙여 저장한다.

```text
실제 후보 점수: 1.0, 2.0, 7.0
힙에 저장한 값: -1.0, -2.0, -7.0
힙의 루트:      -7.0
후보 최댓값:    -heap[0] = 7.0
```

새 점수가 현재 후보의 최댓값보다 작으면 힙의 루트를 새 점수로 교체한다. 그렇지 않으면 새 점수는 최저 7개에 포함될 수 없으므로 버린다.

## 사용한 자료구조

### 리스트(List)

처음 풀이에서는 최대 7개의 점수를 리스트에 저장했다. 전체 `N`개가 아니라 필요한 후보만 저장한다는 점에서 공간을 잘 제한했다.

다만 리스트의 마지막 원소를 최댓값으로 사용하려면 리스트가 항상 정렬되어 있어야 한다. 정렬 상태라는 불변식을 유지하지 않으면 `score[-1]`을 기준으로 후보를 제거할 수 없다.

### 최대 힙(Max Heap)

최종 풀이에서는 `heapq`와 음수 점수를 이용해 최대 힙처럼 사용했다.

```python
heapq.heappush(heap, -current_score)
```

힙에는 항상 가장 낮은 점수 7개의 음수값만 저장한다. 루트인 `heap[0]`에는 가장 작은 음수, 즉 실제 점수로는 후보 중 가장 큰 값이 위치한다.

```python
largest_candidate = -heap[0]
```

새 점수가 더 작다면 `heapreplace()`로 현재 최댓값을 제거하고 새 후보를 넣는다.

```python
heapq.heapreplace(heap, -current_score)
```

힙의 크기는 최대 7이므로 입력 크기와 관계없이 저장 공간이 일정하다.

## 사용한 알고리즘

### 고정 크기 우선순위 큐

지금까지 입력받은 점수 중 가장 낮은 7개만 유지한다.

- 힙의 크기가 7보다 작다: 새 점수를 추가한다.
- 힙의 크기가 7이다: 후보 중 최댓값과 비교한다.
- 새 점수가 더 작다: 기존 최댓값을 새 점수로 교체한다.
- 새 점수가 크거나 같다: 최저 7개에 들어갈 수 없으므로 버린다.

이 과정이 끝나면 힙에는 전체 입력 중 가장 낮은 7개만 남는다.

### 정렬(Sorting)

힙은 최댓값을 빠르게 찾기 위한 자료구조이지 전체 순서를 보장하지 않는다. 따라서 입력 처리가 끝난 뒤 후보 7개만 오름차순으로 정렬한다.

```python
answer = sorted(-value for value in heap)
```

전체 `N`개가 아니라 7개만 정렬하므로 정렬 비용은 매우 작다.

## 시간복잡도

유지할 점수의 개수를 `K = 7`이라고 하자.

- 점수 하나를 힙에 추가하거나 교체: `O(log K)`
- `N`개 점수 처리: `O(N log K)`
- 마지막 7개 정렬: `O(K log K)`
- 전체 시간복잡도: **`O(N log 7)`**, 상수 크기 힙이므로 사실상 **`O(N)`**
- 공간복잡도: **`O(7)`**, 즉 **`O(1)`**

모든 점수를 저장하고 정렬하는 방식의 시간복잡도 `O(N log N)`, 공간복잡도 `O(N)`보다 큰 입력에 적합하다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[학생 점수 하나 입력]
          |
          v
   [힙 크기 < 7 인가?]
       /           \
     Yes           No
      |              |
      v              v
[음수로 변환해]  [현재 후보 최댓값 확인]
 [힙에 추가]       largest = -heap[0]
                     |
                     v
             [새 점수 < largest 인가?]
                  /           \
                Yes           No
                 |              |
                 v              v
          [루트를 새 점수로]  [새 점수 버림]
               [교체]
                  \           /
                   v         v
             [다음 점수 입력]
                      |
                      v
              [N개 입력 완료]
                      |
                      v
       [남은 7개를 실제 점수로 복원]
                      |
                      v
          [오름차순 정렬 후 3자리 출력]
```

## 최종 제출 코드

```python
import sys
import heapq

input = sys.stdin.buffer.readline

N = int(input())
lowest_scores = []

for _ in range(N):
    current_score = float(input())

    if len(lowest_scores) < 7:
        heapq.heappush(lowest_scores, -current_score)
    elif current_score < -lowest_scores[0]:
        heapq.heapreplace(lowest_scores, -current_score)

answer = sorted(-score for score in lowest_scores)

sys.stdout.write('\n'.join(f'{score:.3f}' for score in answer))
```


## 오늘의 회고(실수한 점 포함)

전체 점수를 저장하지 않고 가장 낮은 점수 7개만 유지하려고 한 접근은 좋았다. 입력 크기를 보고 필요한 값의 개수가 고정되어 있다는 점을 활용했기 때문에 공간복잡도를 `O(1)`로 줄일 수 있었다.

다만 다음 세 부분을 놓쳤다.

1. **처음 7개가 정렬되지 않았다.**

   `score[-1]`을 최댓값으로 사용하려면 리스트가 항상 오름차순으로 정렬되어 있어야 한다. 코드에서 어떤 위치의 값에 의미를 부여했다면 그 의미를 보장하는 불변식이 유지되는지 확인해야 한다.

2. **최종 후보를 오름차순으로 정렬하지 않았다.**

   교체가 한 번도 발생하지 않으면 처음 입력된 순서 그대로 남을 수 있다. 문제에서는 낮은 점수부터 출력해야 하므로 마지막 정렬이 필요하다. 힙을 사용해도 내부 배열은 정렬된 상태가 아니기 때문에 출력 전에 정렬해야 한다.

3. **`print(score)`로 리스트 자체를 출력했다.**

   이 코드는 대괄호와 쉼표가 포함된 Python 리스트 표현을 출력한다.

   ```text
   [0.1, 1.2, 2.3, ...]
   ```

   문제에서는 점수를 한 줄에 하나씩, 소수점 셋째 자리까지 출력해야 한다.

   ```python
   for score in answer:
       print(f'{score:.3f}')
   ```

리스트를 단수형 `score`, 현재 입력값을 `i`라고 표현하기보다 `lowest_scores`, `current_score`처럼 역할이 드러나는 이름을 사용하면 비교 대상이 더 명확해진다.

이번 문제를 통해 상위 또는 하위 `K`개만 필요한 문제에서는 전체 데이터를 정렬하기 전에 **크기 `K`의 힙으로 후보만 유지할 수 있는지** 확인해야 한다는 점을 복기했다. 또한 리스트의 특정 위치를 최댓값이나 최솟값으로 사용할 때는 그 순서가 항상 유지되는지 반드시 확인해야 한다.
