## 문제 정의

상근이가 가지고 있는 숫자 카드 `N`개가 주어진다. 이후 정수 `M`개가 주어졌을 때, 각 정수를 적은 숫자 카드를 상근이가 몇 개 가지고 있는지 입력 순서대로 출력하는 문제다.

같은 숫자의 카드가 여러 장 존재할 수 있으므로 단순히 카드의 존재 여부만 확인해서는 안 된다. 각 숫자가 등장한 **횟수**를 저장해야 한다.

예를 들어 가지고 있는 카드가 다음과 같다고 하자.

```text
6 3 2 10 10 10 -10 -10 7 3
```

`10`은 3장, `3`은 2장, 가지고 있지 않은 `5`는 0장이다.

## 접근 및 설계

처음에는 상근이가 가진 카드의 숫자를 `Counter`에 넣어 숫자별 등장 횟수를 한 번에 계산했다.

```python
card_counts = Counter(map(int, input().split()))
```

이후 확인해야 하는 숫자를 앞에서부터 순회하며 `card_counts[number]`를 조회했다. `Counter`는 해당 숫자가 있으면 저장된 개수를 반환하고, 존재하지 않으면 `KeyError` 대신 `0`을 반환하므로 문제의 출력 조건과 잘 맞는다.

이 문제에서 중요한 선택은 매 질문마다 전체 숫자 카드를 다시 세지 않는 것이다.

```text
비효율적인 방법
질문 하나 입력 -> 카드 N개 전체 확인 -> 개수 출력
```

이 방식은 최대 `N × M`번 비교할 수 있다. 대신 처음 한 번만 전체 카드를 순회해 빈도표를 만들면, 이후에는 각 숫자의 개수를 평균 `O(1)`에 조회할 수 있다.

출력해야 하는 숫자의 순서는 입력 순서와 같아야 하므로 조회할 숫자는 `list`에 저장했다. 결과 출력은 반복문 안에서 `print()`를 여러 번 호출하는 대신 문자열 리스트를 만든 뒤 `join()`으로 한 번에 출력하도록 정리했다.

## 사용한 자료구조

### Counter

`collections.Counter`는 각 원소가 몇 번 등장했는지를 저장하는 딕셔너리 계열의 자료구조다.

```python
card_counts = Counter([10, 10, 3, 10, 3])

# Counter({10: 3, 3: 2})
```

- 키: 숫자 카드에 적힌 숫자
- 값: 해당 숫자 카드의 개수
- 없는 키 조회 결과: `0`

직접 딕셔너리를 사용해 개수를 누적할 수도 있지만, `Counter`를 사용하면 빈도 계산이라는 의도가 코드에 명확하게 드러난다.

### 리스트(List)

확인할 `M`개의 숫자를 입력 순서대로 저장하기 위해 리스트를 사용했다.

```python
queries = list(map(int, input().split()))
```

질문의 순서대로 답을 출력해야 하므로 정렬하지 않고 그대로 순회한다.

## 사용한 알고리즘

### 빈도 계산(Frequency Counting)

숫자 카드 `N`개를 한 번 순회하면서 각 숫자의 등장 횟수를 센다. 동일한 숫자가 다시 나오면 해당 숫자의 개수를 1 증가시키는 방식이다.

이 풀이에서는 그 과정을 `Counter`가 대신 수행한다.

### 해시 탐색(Hash Lookup)

`Counter`는 해시 기반 딕셔너리처럼 숫자를 키로 사용한다. 따라서 확인할 숫자마다 전체 카드를 다시 탐색하지 않고, 해당 숫자의 개수를 평균 `O(1)`에 조회할 수 있다.

정렬 후 이분 탐색으로 각 숫자의 범위를 찾는 방법도 있지만, 이 문제에서는 개수만 필요하므로 빈도표를 만드는 방법이 더 직접적이다.

## 시간복잡도

서로 다른 카드 숫자의 개수를 `U`라고 하자.

- 숫자 카드 `N`개의 빈도 계산: `O(N)`
- 확인할 숫자 `M`개의 개수 조회: `O(M)`
- 출력 문자열 생성: `O(M)`
- 전체 시간복잡도: **`O(N + M)`**
- 공간복잡도: 빈도표 `O(U)`, 조회 숫자와 결과 `O(M)`이므로 **`O(U + M)`**

`U`는 최대 `N`이므로 공간복잡도를 크게 표현하면 `O(N + M)`이다.

매 질문마다 카드 전체를 확인하는 완전 탐색 `O(NM)`과 비교하면 입력 크기가 커질수록 차이가 크게 난다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[숫자 카드 N개 입력]
          |
          v
[Counter로 숫자별 등장 횟수 계산]
          |
          v
예: {-10: 2, 3: 2, 10: 3, ...}
          |
          v
[확인할 숫자 M개를 입력 순서대로 순회]
          |
          v
[Counter에서 해당 숫자의 개수 조회]
       /                    \
  키가 있음                키가 없음
      |                         |
      v                         v
[저장된 개수 반환]          [0 반환]
       \                    /
        v                  v
   [결과를 문자열 리스트에 저장]
                 |
                 v
     [join으로 공백을 넣어 한 번에 출력]
```

## 최종 제출 코드

```python
import sys
from collections import Counter

input = sys.stdin.readline

N = int(input())
card_counts = Counter(map(int, input().split()))

M = int(input())
queries = list(map(int, input().split()))

answer = [str(card_counts[number]) for number in queries]
sys.stdout.write(' '.join(answer))
```

로컬 테스트를 위해 사용한 아래 코드는 백준 제출 시 제거해야 한다.

```python
sys.stdin = open('./input/number_card2_input.txt', 'r')
```

## 오늘의 회고(실수한 점 포함)

이번 풀이에서는 문제를 보자마자 숫자별 개수를 저장해야 한다고 판단해 `Counter`를 사용했다. 카드가 존재하는지만 확인하는 `set`이 아니라, 중복 개수까지 보존하는 자료구조가 필요하다는 점을 잘 구분했다.

또한 카드 목록을 정렬하거나 각 질문마다 다시 순회하지 않고, 빈도를 한 번 계산한 뒤 조회하는 방식으로 `O(N + M)`에 해결했다. 입력값에 음수가 포함되어도 숫자를 딕셔너리의 키로 사용하므로 별도의 처리가 필요하지 않다.

복기할 부분은 출력 방식이다. 처음 작성한 다음 코드도 결과는 올바르다.

```python
for num in num_2:
    print(num_1[num], end=' ')
```

하지만 `M`이 최대 50만이므로 `print()`를 반복 호출하는 것보다 답을 문자열로 변환해 `join()`으로 한 번에 출력하는 편이 입출력 비용을 줄이고 코드의 출력 의도도 명확하게 보여 준다.

변수명도 `num_1`, `num_2`보다는 `card_counts`, `queries`처럼 역할이 드러나는 이름을 사용하면 나중에 코드를 복기할 때 자료의 의미를 빠르게 파악할 수 있다.

이번 문제를 통해 값의 존재 여부가 아니라 **등장 횟수**를 반복해서 묻는 문제에서는 먼저 해시 기반 빈도표를 만들 수 있는지 확인해야 한다는 점을 정리했다. Python에서는 `Counter`가 이 패턴을 가장 간결하게 표현해 준다.
