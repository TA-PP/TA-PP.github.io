## 문제 정의

[프로그래머스 입국심사](https://school.programmers.co.kr/learn/courses/30/lessons/43238)는 입국심사를 기다리는 `n`명과 각 심사관이 한 명을 심사하는 데 걸리는 시간이 담긴 `times`가 주어질 때, 모든 사람이 심사를 마치는 데 필요한 최소 시간을 구하는 문제다.

모든 심사대는 처음에 비어 있고, 한 심사대에서는 동시에 한 명만 심사할 수 있다. 어떤 사람이 비어 있는 심사대로 바로 가지 않고 더 빠른 심사대를 기다리는 것이 전체 시간을 줄일 수도 있다.

예를 들어 `n = 6`, `times = [7, 10]`이라면 정답은 28분이다.

```text
28분 동안 첫 번째 심사관이 처리한 사람: 28 // 7  = 4명
28분 동안 두 번째 심사관이 처리한 사람: 28 // 10 = 2명
총 6명
```

`n`이 최대 10억이므로 사람을 한 명씩 심사대에 배정하는 시뮬레이션으로 접근하기보다, 시간의 최솟값을 이분 탐색해야 한다.

## 접근 및 설계

처음부터 정답 코드를 바로 작성하지는 못했고, 네 단계에 걸쳐 조건과 반환값을 수정했다. 이 과정을 복기하면서 이분 탐색에서 무엇을 기준으로 범위를 이동해야 하는지 정리했다.

### 1단계: 심사한 사람 수를 반환

```python
if count > n:
    right = mid - 1
elif count < n:
    left = mid + 1

return count
```

첫 시도에서는 `mid`분 동안 심사할 수 있는 사람 수를 계산했지만, 문제에서 요구하는 값은 사람 수가 아니라 **모든 사람의 심사가 끝나는 최소 시간**이다. 따라서 `count`를 반환하면 문제의 요구사항과 맞지 않는다.

더 큰 문제는 `count == n`일 때 `left`와 `right`가 모두 바뀌지 않는다는 점이다. 같은 `mid`를 계속 검사하게 되어 무한 루프가 발생한다. 이분 탐색의 모든 분기에서는 반드시 탐색 구간이 줄어들어야 한다.

### 2단계: `count == n`이면 즉시 종료

```python
if count > n:
    right = mid - 1
elif count < n:
    left = mid + 1
else:
    break

return mid
```

두 번째 시도에서는 무한 루프를 피하기 위해 `count == n`이면 반복을 끝냈다. 하지만 정확히 `n`명을 처리할 수 있다는 사실만으로 현재 시간이 최소라는 보장은 없다.

```text
n = 3, times = [2, 3]

4분: 4 // 2 + 4 // 3 = 2 + 1 = 3명  <- 최소 시간
5분: 5 // 2 + 5 // 3 = 2 + 1 = 3명  <- 역시 3명
```

처음 확인한 시간이 5분이라면 `count == n`이므로 바로 종료하지만, 실제 정답은 4분이다. 같은 사람 수를 처리할 수 있는 시간이 여러 개일 수 있으므로 동일 조건을 찾는 것이 아니라 **조건을 처음 만족하는 경계**를 찾아야 한다.

또한 처리 인원은 동시에 여러 심사가 끝날 때 2명 이상 증가할 수 있다.

```text
n = 3, times = [1, 1]

1분: 2명
2분: 4명
```

이 경우 `count == 3`인 시간은 아예 존재하지 않지만, 2분이면 3명 모두 심사를 받을 수 있다. 따라서 판단 조건은 `count == n`이 아니라 `count >= n`이어야 한다.

### 3단계: `count == n`인 시간을 리스트에 저장

```python
if count >= n:
    right = mid - 1
else:
    left = mid + 1

if count == n:
    correct.append(mid)
```

세 번째 시도에서는 `count >= n`이면 왼쪽 구간을 탐색하도록 경계 이동은 올바르게 수정했다. 하지만 여전히 `count == n`인 시간만 `correct`에 저장했다.

앞의 `n = 3`, `times = [1, 1]`처럼 처리 인원이 2명에서 4명으로 건너뛰면 리스트가 비어 있어 `min(correct)`에서 오류가 발생한다. 정답 후보는 정확히 `n`명을 처리하는 시간이 아니라 **`n`명 이상을 처리할 수 있는 모든 시간**이다.

### 4단계: 가능한 시간을 모두 저장

```python
if count >= n:
    right = mid - 1
    correct.append(mid)
else:
    left = mid + 1

return min(correct)
```

네 번째 시도에서는 `count >= n`인 모든 `mid`를 정답 후보로 저장했기 때문에 올바른 답을 구할 수 있다. 이 단계에서 핵심 이분 탐색 조건은 완성됐다.

다만 후보를 리스트에 저장할 필요는 없다. 반복이 끝났을 때 `left`가 조건을 만족하는 최초의 시간, 즉 모든 사람의 심사가 끝나는 최소 시간을 가리키기 때문이다.

최종 설계는 다음과 같다.

- `count >= n`: `mid`분이면 충분하다. 더 짧은 시간이 가능한지 확인한다.
- `count < n`: `mid`분으로는 부족하다. 시간을 늘린다.
- 반복 종료 후: `left`가 최초로 가능한 시간이다.

## 사용한 자료구조

### 리스트(List)

각 심사관의 심사 시간을 `times` 리스트로 전달받는다.

```python
times = [7, 10]
```

후보 시간 `mid`가 바뀔 때마다 모든 심사관을 순회하며 처리할 수 있는 사람 수를 더한다. 심사 시간의 입력 순서는 결과에 영향을 주지 않으므로 정렬은 필요하지 않다.

네 번째 시도에서는 가능한 시간을 저장하기 위해 `correct` 리스트를 추가했지만, 최종 코드에서는 이분 탐색의 종료 경계를 정답으로 사용하므로 별도의 후보 리스트가 필요 없다.

## 사용한 알고리즘

### 이분 탐색(Binary Search)

탐색 대상은 심사관이나 사람이 아니라 **모든 사람의 심사가 끝나는 데 걸리는 시간**이다.

탐색 범위는 다음과 같이 설정한다.

```python
left = 1
right = min(times) * n
```

- 최소 시간은 1분이다.
- 가장 빠른 심사관이 혼자 `n`명을 모두 처리하는 시간은 반드시 가능한 상한이다.

처음 사용한 `max(times) * n`도 정답을 포함하는 안전한 상한이지만, `min(times) * n`이 더 작은 범위이므로 탐색 의도가 명확하고 반복 횟수도 줄일 수 있다.

### 매개변수 탐색(Parametric Search)

최소 시간을 직접 계산하는 대신 다음 결정 문제로 바꾼다.

> `mid`분 안에 `n`명 이상을 심사할 수 있는가?

`mid`분 동안 심사관 한 명이 처리할 수 있는 사람 수는 `mid // time`명이다. 모든 심사관의 처리 인원을 더하면 해당 시간에 처리할 수 있는 전체 인원을 구할 수 있다.

```python
count = sum(mid // time for time in times)
```

시간이 늘어날수록 처리할 수 있는 사람 수는 감소하지 않는다.

```text
시간:             짧음 ---------------------------> 길어짐
n명 이상 심사:    불가능 불가능 불가능 | 가능 가능 가능
                                      ↑
                              찾아야 할 첫 가능 시간
```

이 단조성을 이용해 조건을 처음 만족하는 시간의 경계를 찾는다.

## 시간복잡도

심사관 수를 `K`, 가장 빠른 심사 시간을 `T`, 기다리는 사람 수를 `n`이라고 하자.

- 한 번의 가능 여부 확인: 심사관 `K`명을 순회하므로 `O(K)`
- 시간 범위 이분 탐색: `O(log(T × n))`
- 전체 시간복잡도: **`O(K log(T × n))`**
- 추가 공간복잡도: **`O(1)`**

입력으로 주어진 `times` 리스트의 공간까지 포함하면 `O(K)`다. 네 번째 시도의 `correct` 리스트는 최대 이분 탐색 횟수만큼 공간을 사용하지만, 최종 코드에서는 제거했다.

`n`과 심사 시간이 최대 10억이어도 시간 범위를 절반씩 줄이므로 충분히 탐색할 수 있다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[n과 times 입력]
          |
          v
[시간 범위 설정]
left = 1, right = min(times) × n
          |
          v
[mid분 동안 처리 가능한 인원 계산]
count = Σ(mid // time)
          |
          v
      count >= n 인가?
       /              \
     Yes              No
      |                 |
      v                 v
[시간은 충분함]      [시간이 부족함]
right = mid - 1      left = mid + 1
       \               /
        v             v
    [left <= right 동안 반복]
               |
               v
[left = n명을 처리할 수 있는 최초 시간]
               |
               v
          [left 반환]
```

## 최종 제출 코드

```python
def solution(n, times):
    left = 1
    right = min(times) * n

    while left <= right:
        mid = (left + right) // 2
        count = 0

        for time in times:
            count += mid // time

        if count >= n:
            right = mid - 1
        else:
            left = mid + 1

    return left
```

처리 인원 계산 중 이미 `n`명 이상임을 확인했다면 나머지 심사관을 확인하지 않아도 된다. 다음과 같이 조기 종료를 추가할 수도 있다.

```python
for time in times:
    count += mid // time
    if count >= n:
        break
```

## 오늘의 회고(실수한 점 포함)

이번 문제는 네 번의 수정을 거치며 이분 탐색의 목표를 구체화했다.

처음에는 `mid`분 동안 처리한 사람 수인 `count`에 집중했지만, 실제로 찾아야 하는 값은 시간이었다. 이후 `count == n`을 발견하면 답이라고 생각했지만, 같은 인원을 처리할 수 있는 시간이 여러 개일 수 있고 처리 인원이 `n`을 건너뛸 수도 있다는 점을 놓쳤다.

핵심은 다음 두 문장을 구분하는 것이다.

```text
잘못 설정한 목표: 정확히 n명을 처리할 수 있는 시간을 찾는다.
올바른 목표:      n명 이상을 처리할 수 있는 최초 시간을 찾는다.
```

세 번째와 네 번째 시도를 통해 `count >= n`일 때 왼쪽 구간을 계속 탐색해야 한다는 점은 잡아냈다. 마지막에는 가능한 값을 모두 `correct`에 저장했지만, 이분 탐색의 종료 조건을 이해하면 `left` 자체가 최솟값이라는 것을 알 수 있다.

앞으로 최솟값을 찾는 이분 탐색에서는 다음을 먼저 적고 구현해야겠다.

1. 결정 함수가 참이 되는 조건은 무엇인가?
2. 참이 처음 나타나는 값과 거짓이 마지막으로 나타나는 값 중 무엇을 찾는가?
3. 반복 종료 후 `left`와 `right`는 각각 어느 경계를 가리키는가?
4. `==` 조건이 반드시 등장한다는 보장이 있는가?

이번 문제의 답은 “`n`명 이상 심사 가능”이 처음 참이 되는 시간이다. 따라서 `count >= n`을 기준으로 범위를 줄이고, 반복이 끝난 뒤 `left`를 반환하는 것이 가장 간결한 풀이가 된다.
