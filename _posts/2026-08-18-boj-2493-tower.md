## 문제 정의

[백준 2493번 탑](https://www.acmicpc.net/problem/2493)은 일렬로 세워진 탑들이 왼쪽으로 레이저 신호를 보낼 때, 각 탑의 신호를 가장 먼저 수신하는 탑의 번호를 구하는 문제다.

현재 탑의 왼쪽에 있으면서 높이가 현재 탑보다 크거나 같은 탑 중 가장 가까운 탑이 신호를 수신한다. 그런 탑이 없다면 `0`을 출력한다.

```text
탑 높이: 6 9 5 7 4
탑 번호: 1 2 3 4 5
수신 탑: 0 0 2 2 4
```

- 1번 탑의 왼쪽에는 탑이 없으므로 `0`
- 2번 탑보다 왼쪽에 더 높은 탑이 없으므로 `0`
- 3번 탑의 신호는 높이 9인 2번 탑이 수신
- 4번 탑의 신호도 높이 9인 2번 탑이 수신
- 5번 탑의 신호는 높이 7인 4번 탑이 수신

`N`이 최대 500,000이므로 각 탑에서 왼쪽을 하나씩 다시 탐색하는 `O(N²)` 풀이는 사용할 수 없다.

## 접근 및 설계

작성한 코드에서는 배열의 오른쪽부터 왼쪽으로 순회했다.

```python
for i in range(N - 1, -1, -1):
    while stack and towers[stack[-1]] < towers[i]:
        answer[stack.pop()] = towers[i]

    stack.append(i)
```

스택에는 아직 왼쪽에서 수신 탑을 찾지 못한 오른쪽 탑의 인덱스를 저장한다. 현재 탑이 스택의 마지막 탑보다 높다면 현재 탑이 그 오른쪽 탑의 신호를 수신한다는 접근이다.

이 방향과 스택 사용은 핵심 알고리즘에 맞다. 다만 문제 조건과 출력 형식에 맞게 네 부분을 수정해야 한다.

### 1. 높이가 아니라 탑 번호를 기록해야 한다

현재 코드는 수신 탑의 높이를 정답에 넣었다.

```python
answer[stack.pop()] = towers[i]
```

문제에서 요구하는 값은 높이가 아니라 왼쪽부터 1번으로 시작하는 **탑의 번호**다. Python 인덱스 `i`는 0부터 시작하므로 `i + 1`을 저장해야 한다.

```python
answer[stack.pop()] = i + 1
```

예제 수열 `6 9 5 7 4`에서 3번 탑과 4번 탑의 수신 탑은 높이 `9`가 아니라 탑 번호 `2`다.

### 2. 수신 탑이 없을 때는 `-1`이 아니라 `0`이다

현재 정답 배열은 `-1`로 초기화했다.

```python
answer = [-1] * N
```

하지만 문제에서는 신호를 수신하는 탑이 없을 때 `0`을 출력해야 한다. 정답 배열을 처음부터 `0`으로 만들면 끝까지 스택에 남아 수신 탑을 찾지 못한 인덱스를 별도로 처리하지 않아도 된다.

```python
answer = [0] * N
```

### 3. 같은 높이의 탑도 신호를 수신한다

작성한 비교 조건은 현재 탑이 더 높은 경우만 처리한다.

```python
towers[stack[-1]] < towers[i]
```

탑 문제에서는 왼쪽 탑의 높이가 현재 탑보다 크거나 같으면 신호를 수신할 수 있다. 따라서 같은 높이도 스택에서 꺼내야 한다.

```python
towers[stack[-1]] <= towers[i]
```

다음 반례에서 차이가 드러난다.

```text
탑 높이: 5 5
올바른 답: 0 1
```

2번 탑의 신호는 같은 높이인 1번 탑이 수신한다. `<` 조건을 사용하면 2번 탑을 스택에서 꺼내지 못하지만 `<=`라면 1번 탑을 수신 탑으로 기록한다.

### 4. 리스트 표현이 아니라 공백으로 출력해야 한다

```python
print(answer)
```

이 코드는 대괄호와 쉼표가 포함된 Python 리스트 표현을 출력한다.

```text
[0, 0, 2, 2, 4]
```

문제에서 요구하는 형식은 다음과 같다.

```text
0 0 2 2 4
```

최종 코드에서는 정답을 문자열로 변환해 공백으로 연결한다.

```python
sys.stdout.write(' '.join(map(str, answer)))
```

### 역방향 순회의 의미

오른쪽에서 왼쪽으로 이동하면 현재 인덱스 `i`는 스택에 있는 모든 탑보다 왼쪽에 있다.

스택의 마지막 탑보다 현재 탑이 높거나 같다면 현재 탑은 그 오른쪽 탑을 수신할 수 있다. 또한 오른쪽에서부터 한 칸씩 왼쪽으로 이동하고 있으므로 현재 탑은 해당 탑이 처음 만난 수신 가능한 탑, 즉 가장 가까운 수신 탑이다.

```python
while stack and towers[stack[-1]] <= towers[i]:
    target = stack.pop()
    answer[target] = i + 1
```

현재 탑이 여러 오른쪽 탑보다 높다면 그 탑들을 한 번에 해결할 수 있다.

## 사용한 자료구조

### 리스트(List)

탑의 높이를 입력 순서대로 `towers`에 저장한다.

```python
towers = list(map(int, input().split()))
```

정답 배열은 수신 탑이 없는 경우의 기본값인 `0`으로 초기화한다.

```python
answer = [0] * N
```

수신 탑을 발견한 인덱스만 `i + 1`로 갱신한다.

### 단조 스택(Monotonic Stack)

스택에는 아직 수신 탑을 찾지 못한 오른쪽 탑의 인덱스를 저장한다.

```python
stack.append(i)
```

스택이 가리키는 탑의 높이는 아래에서 위로 갈수록 엄격하게 감소한다.

```text
towers[stack[0]] > towers[stack[1]] > ... > towers[stack[-1]]
```

현재 탑보다 작거나 같은 오른쪽 탑은 모두 스택에서 제거되기 때문이다.

현재 탑이 스택의 마지막 탑보다 낮다면, 스택 아래쪽에는 마지막 탑보다 더 높은 탑들만 있다. 따라서 현재 탑은 스택 안의 어떤 탑도 수신할 수 없으므로 비교를 멈추고 현재 인덱스를 추가할 수 있다.

## 사용한 알고리즘

### 역방향 단조 스택

탑을 오른쪽에서 왼쪽으로 한 번 순회한다.

1. 현재 탑의 높이가 스택 마지막 탑보다 크거나 같은지 확인한다.
2. 조건을 만족하면 스택의 탑을 꺼낸다.
3. 꺼낸 탑의 정답을 현재 탑 번호 `i + 1`로 기록한다.
4. 더 이상 수신할 수 있는 탑이 없을 때까지 반복한다.
5. 현재 탑 인덱스를 스택에 넣는다.

```python
for i in range(N - 1, -1, -1):
    while stack and towers[stack[-1]] <= towers[i]:
        answer[stack.pop()] = i + 1

    stack.append(i)
```

### 오큰수 문제와의 관계

앞서 푼 오큰수 문제와 둘 다 단조 스택으로 “가장 가까운 조건 만족 원소”를 찾는다.

```text
오큰수: 현재 원소의 오른쪽에서 처음 만나는 더 큰 값
탑:     현재 탑의 왼쪽에서 처음 만나는 크거나 같은 값의 위치
```

오큰수는 왼쪽에서 오른쪽으로 이동하며 이전 인덱스의 답을 현재 값으로 해결했다. 이번 탑 풀이는 오른쪽에서 왼쪽으로 이동하며 오른쪽 인덱스의 답을 현재 탑 번호로 해결한다.

문제에서 찾는 방향에 맞춰 순회 방향을 바꾸면 동일한 “미해결 인덱스를 스택에 보관한다”는 패턴을 사용할 수 있다.

## 시간복잡도

- 탑 높이 입력 및 저장: `O(N)`
- 각 인덱스를 스택에 한 번 추가: `O(N)`
- 각 인덱스를 스택에서 최대 한 번 제거: `O(N)`
- 결과 문자열 생성 및 출력: `O(N)`
- 전체 시간복잡도: **`O(N)`**
- 공간복잡도: **`O(N)`**

`for`문 안에 `while`문이 있지만 각 탑 인덱스는 전체 실행에서 한 번 들어가고 최대 한 번 나온다. 따라서 전체 `pop()` 횟수는 최대 `N`번이며 `O(N²)`이 아니다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[answer를 N개의 0으로 초기화]
                |
                v
[오른쪽 끝 탑부터 현재 인덱스 i 확인]
                |
                v
           [스택이 비었는가?]
             /          \
           Yes          No
            |            |
            |            v
            | [오른쪽 탑 높이 <= 현재 탑 높이?]
            |          /               \
            |        Yes               No
            |         |                 |
            |         v                 |
            |   [오른쪽 인덱스 pop]      |
            |   [answer[target] = i + 1]|
            |         |                 |
            |   [조건 다시 확인]         |
            |         \                /
            |          v              v
            +----> [현재 인덱스를 push]
                          |
                          v
                  [다음 왼쪽 탑 확인]
                          |
                          v
                  [모든 탑 처리 완료]
                          |
                          v
              [answer를 공백으로 연결해 출력]
```

## 최종 제출 코드

```python
import sys

input = sys.stdin.buffer.readline

N = int(input())
towers = list(map(int, input().split()))

answer = [0] * N
stack = []

for i in range(N - 1, -1, -1):
    while stack and towers[stack[-1]] <= towers[i]:
        answer[stack.pop()] = i + 1

    stack.append(i)

sys.stdout.write(' '.join(map(str, answer)))
```

로컬 테스트를 위해 사용한 아래 코드는 백준 제출 시 제거해야 한다.

```python
sys.stdin = open('./input/tower_input.txt', 'r')
```

## 오늘의 회고(실수한 점 포함)

오큰수 문제에서 사용한 인덱스 단조 스택을 반대 방향으로 적용하려고 한 접근은 좋았다. 오른쪽에서 왼쪽으로 순회하면서 현재 탑이 수신할 수 있는 오른쪽 탑을 한 번에 꺼내는 구조는 `O(N)` 풀이의 핵심이다.

다만 비슷한 문제의 코드를 옮겨 적용할 때 문제별로 달라지는 출력값과 경계 조건을 놓쳤다.

1. **수신 탑의 높이를 기록했다.**

   문제는 수신 탑의 높이가 아니라 번호를 요구한다. 인덱스를 사용하는 문제에서는 답이 값인지 위치인지 먼저 확인해야 한다. 0부터 시작하는 Python 인덱스도 문제의 1번 기반 번호에 맞게 `i + 1`로 변환해야 한다.

2. **기본값을 `-1`로 설정했다.**

   오큰수 문제에서는 답이 없을 때 `-1`이었지만 탑 문제에서는 `0`이다. 알고리즘 패턴이 같아도 문제의 출력 규칙까지 같다고 가정하면 안 된다.

3. **같은 높이를 처리하지 않았다.**

   오큰수는 엄격하게 큰 값만 답이지만 탑은 높이가 같은 탑도 신호를 수신한다. 따라서 비교 연산자가 `<`에서 `<=`로 달라진다. 단조 스택 문제에서는 중복값 처리 조건이 정답을 자주 바꾸므로 반드시 반례를 확인해야 한다.

4. **리스트 자체를 출력했다.**

   `print(answer)`는 대괄호와 쉼표를 포함한다. 제출 전에 문제에서 요구하는 공백 구분 출력인지 확인해야 한다.

5. **스택의 역할은 값 저장이 아니라 미해결 위치 추적이다.**

   스택에 인덱스를 넣으면 높이 비교에는 `towers[index]`를 사용하고, 정답 기록에는 해당 인덱스를 그대로 사용할 수 있다. 위치별 답을 요구하는 문제에서 인덱스 스택이 유용한 이유다.

이번 문제를 통해 오큰수와 탑처럼 구조가 비슷한 문제는 **탐색 방향, 엄격한 비교인지 이상·이하 비교인지, 답으로 값과 위치 중 무엇을 요구하는지, 답이 없을 때의 기본값**을 표로 비교하며 복기해야 한다는 점을 확인했다. 알고리즘 패턴을 재사용하되 문제의 경계 조건은 새로 읽는 습관이 중요하다.
