## 문제 정의

[백준 20922번 겹치는 건 싫어](https://www.acmicpc.net/problem/20922)는 길이 `N`인 수열에서 같은 정수가 `K`개 이하로 포함되는 가장 긴 연속 부분 수열의 길이를 구하는 문제다.

여기서 조건은 모든 종류의 정수가 각각 `K`개 이하로 등장해야 한다는 뜻이다.

```text
K = 2

[3, 2, 5, 5, 6, 4, 4]
5의 개수: 2
4의 개수: 2
조건 만족

[3, 2, 5, 5, 6, 4, 4, 5]
5의 개수: 3
조건 위반
```

주요 제한은 다음과 같다.

- `1 <= N <= 200,000`
- `1 <= K <= 100`
- 각 원소는 100,000 이하의 양의 정수다.

모든 연속 구간을 만들고 내부 원소의 개수를 세면 `O(N²)` 이상의 시간이 필요하다. `N`이 최대 200,000이므로 현재 구간을 재사용하는 슬라이딩 윈도우가 필요하다.

## 접근 및 설계

작성한 코드는 `left`와 `right`로 현재 연속 구간을 표현하고, 딕셔너리에 각 원소의 등장 횟수를 저장하려고 했다.

```python
left = 0
right = 1
count = {}
count[numbers[left]] = 1
```

구간에 같은 숫자가 `K`개보다 많이 들어오면 `left`를 이동해 윈도우를 줄이고, 조건을 만족하면 `right`를 이동해 윈도우를 확장한다는 전체 방향은 맞다.

다만 구현에는 다음 네 가지 수정이 필요하다.

### 문제 1: 구간 길이가 1 작게 계산된다

작성한 코드에서는 다음 값을 정답 후보로 저장했다.

```python
answer.append(right - left)
```

현재 구간이 양 끝을 모두 포함하는 `[left, right]`라면 길이는 다음과 같다.

```text
right - left + 1
```

예를 들어 `numbers = [1, 2, 3, 4]`, `K = 1`이면 전체 수열이 조건을 만족하므로 정답은 4다. 하지만 작성한 코드는 후보를 1, 2, 3으로 저장해 최종적으로 3을 출력한다.

### 문제 2: 제한을 위반한 구간을 후보로 저장한다

오른쪽 원소를 추가한 직후 바로 길이를 저장한다.

```python
count[numbers[right]] = count.get(numbers[right], 0) + 1
answer.append(right - left)
```

새 원소를 추가하면서 해당 숫자의 등장 횟수가 `K + 1`이 될 수 있다. 이때 현재 윈도우는 아직 조건을 위반한 상태다.

정답 길이는 `left`를 충분히 이동해 위반을 해소한 다음 갱신해야 한다.

### 문제 3: max(count.values())를 매번 계산한다

```python
if max(count.values()) > K:
```

딕셔너리 값 전체의 최댓값을 구하려면 현재 저장된 서로 다른 원소의 개수를 `D`라고 할 때 `O(D)`가 필요하다. 이를 포인터가 움직일 때마다 반복하면 최악의 경우 `O(ND)`, 즉 `O(N²)`에 가까워질 수 있다.

기존 윈도우는 이미 조건을 만족하고 있었다. 여기에 새로 추가한 `numbers[right]`만 등장 횟수가 증가했으므로, 조건을 새롭게 위반할 수 있는 숫자도 이 값 하나뿐이다.

따라서 다음 값만 확인하면 된다.

```python
count[numbers[right]] > K
```

### 문제 4: N이 1이면 후보 리스트가 비어 있다

`right = 1`에서 시작하므로 `N = 1`이면 반복문에 진입하지 않는다. `answer`도 빈 리스트인 상태이므로 `max(answer)`에서 `ValueError`가 발생한다.

두 포인터를 모두 0부터 시작하거나, `right`를 `for`문으로 순회하면 별도의 예외 처리 없이 길이 1인 수열도 확인할 수 있다.

### 수정한 설계

오른쪽 포인터를 0부터 끝까지 순회하며 새 원소를 현재 윈도우에 추가한다.

```python
for right in range(N):
    current = numbers[right]
    count[current] = count.get(current, 0) + 1
```

방금 추가한 원소의 개수가 `K`를 초과했다면 조건을 만족할 때까지 왼쪽 원소를 제거한다.

```python
while count[current] > K:
    count[numbers[left]] -= 1
    left += 1
```

이 반복문이 끝나면 `[left, right]`는 항상 유효한 구간이다. 그때 구간 길이로 최댓값을 갱신한다.

```python
answer = max(answer, right - left + 1)
```

## 사용한 자료구조

### 리스트(List)

입력 수열을 원래 순서 그대로 저장한다.

```python
numbers = list(map(int, input().split()))
```

이 문제는 연속 부분 수열을 구하므로 정렬하면 안 된다. 정렬하면 원래 수열에서 어떤 원소들이 서로 붙어 있었는지 알 수 없게 된다.

### 딕셔너리(Dictionary)

현재 `[left, right]` 구간에서 각 숫자가 몇 번 등장하는지 저장한다.

```python
count = {}
count[current] = count.get(current, 0) + 1
```

- 키: 수열에 등장한 숫자
- 값: 현재 윈도우 안에서 해당 숫자가 등장한 횟수

딕셔너리의 조회와 갱신은 평균적으로 `O(1)`이다. 현재 구간에서 실제로 등장한 숫자만 저장하므로 서로 다른 원소의 개수를 `D`라고 할 때 `O(D)`의 공간을 사용한다.

### 빈도 배열을 사용하는 방법

수열 원소가 100,000 이하라는 제한을 이용하면 딕셔너리 대신 다음과 같은 리스트를 사용할 수도 있다.

```python
count = [0] * 100001
```

숫자를 그대로 인덱스로 사용하므로 조회와 갱신이 `O(1)`이며 해시 연산이 없다. 다만 입력에서 등장하지 않는 숫자의 공간도 미리 확보한다.

이번 글의 최종 코드에서는 처음 사용한 자료구조를 살려 딕셔너리를 사용한다.

### 최대 길이 변수

작성한 코드에서는 모든 길이 후보를 리스트에 저장한 다음 최댓값을 구했다.

```python
answer.append(right - left)
print(max(answer))
```

문제에서 필요한 값은 가장 긴 길이 하나뿐이다. 후보 전체를 저장하지 않고 정수 변수 하나를 바로 갱신할 수 있다.

```python
answer = max(answer, right - left + 1)
```

이렇게 하면 후보 리스트를 위한 추가 공간을 사용하지 않고 빈 리스트 예외도 피할 수 있다.

## 사용한 알고리즘

### 슬라이딩 윈도우

`[left, right]`를 현재 확인 중인 연속 부분 수열로 두고 오른쪽으로 이동시킨다.

```python
for right in range(N):
    current = numbers[right]
    count[current] = count.get(current, 0) + 1

    while count[current] > K:
        count[numbers[left]] -= 1
        left += 1

    answer = max(answer, right - left + 1)
```

오른쪽 원소를 추가해 구간을 확장하고, 조건을 위반하면 왼쪽 원소를 제거해 구간을 축소한다.

### 현재 원소의 개수만 확인해도 되는 이유

새 원소를 추가하기 전의 윈도우는 모든 원소의 등장 횟수가 `K` 이하인 유효한 상태다.

오른쪽 원소를 하나 추가하면 오직 `numbers[right]`의 개수만 1 증가한다. 다른 숫자의 개수는 바뀌지 않으므로 새롭게 `K`를 초과할 수 있는 숫자는 `numbers[right]`뿐이다.

```text
추가 전: 모든 count[value] <= K
추가 후: count[numbers[right]]만 1 증가

확인할 값: count[numbers[right]]
```

이 관찰 덕분에 `max(count.values())`로 모든 빈도를 순회할 필요가 없다.

### while로 왼쪽을 이동하는 이유

조건을 위반했을 때 `left`를 한 번만 이동한다고 반드시 문제가 해결되는 것은 아니다. 추가된 숫자와 같은 값이 윈도우의 더 오른쪽에 있을 수 있다.

```python
while count[current] > K:
    count[numbers[left]] -= 1
    left += 1
```

`current`의 개수가 다시 `K`가 될 때까지 왼쪽 원소를 계속 제거해야 한다.

### 예제 흐름

```text
N = 9, K = 2
numbers = [3, 2, 5, 5, 6, 4, 4, 5, 7]
```

`right = 6`까지 확장하면 다음 구간이 만들어진다.

```text
[3, 2, 5, 5, 6, 4, 4]

count[5] = 2
count[4] = 2
길이 = 7
조건 만족
```

다음 `5`를 추가하면 `count[5] = 3`이 되어 조건을 위반한다.

```text
[3, 2, 5, 5, 6, 4, 4, 5]
```

왼쪽을 이동하며 3과 2를 제거해도 5의 개수는 여전히 3이다. 첫 번째 5를 제거한 뒤에야 `count[5] = 2`가 되어 다시 유효한 구간이 된다.

최대 길이는 7이므로 정답은 7이다.

## 시간복잡도

수열의 길이를 `N`, 현재까지 등장한 서로 다른 숫자의 개수를 `D`라고 하자.

### 수정한 풀이

- `right` 포인터 이동: 최대 `N`번
- `left` 포인터 이동: 최대 `N`번
- 딕셔너리 조회 및 갱신: 평균 `O(1)`
- 전체 시간복잡도: **평균 `O(N)`**
- 입력 리스트를 포함한 공간복잡도: **`O(N + D)`**, 전체적으로 `O(N)`
- 빈도 딕셔너리의 추가 공간: **`O(D)`**

코드에 `for`문 안의 `while`문이 있지만 `left`는 전체 실행 동안 뒤로 이동하지 않는다. 각 원소는 오른쪽 포인터에 의해 한 번 들어오고 왼쪽 포인터에 의해 최대 한 번 빠지므로 전체 이동 횟수는 선형이다.

### 작성한 코드

작성한 코드의 `max(count.values())`는 한 번 계산할 때 `O(D)`가 필요하다. 이 연산을 포인터 이동마다 수행하므로 최악의 시간복잡도는 **`O(ND)`**, 서로 다른 값이 많으면 **`O(N²)`**까지 커질 수 있다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[N, K와 수열 입력]
          |
          v
[left = 0, count = {}, answer = 0]
          |
          v
[right를 0부터 N-1까지 이동]
          |
          v
[numbers[right]의 등장 횟수 +1]
          |
          v
[방금 추가한 숫자의 개수 > K?]
       /                       \
     Yes                        No
      |                          |
      v                          |
[numbers[left]의 개수 -1]        |
      |                          |
      v                          |
[left 한 칸 이동]                |
      |                          |
      +-- 여전히 K 초과면 반복   |
       \                        /
        v                      v
 [유효한 구간 길이 = right-left+1]
                    |
                    v
          [answer 최댓값 갱신]
                    |
                    v
             [다음 right 확인]
                    |
                    v
              [answer 출력]
```

## 최종 제출 코드

```python
import sys

input = sys.stdin.readline

N, K = map(int, input().split())
numbers = list(map(int, input().split()))

left = 0
count = {}
answer = 0

for right in range(N):
    current = numbers[right]
    count[current] = count.get(current, 0) + 1

    while count[current] > K:
        count[numbers[left]] -= 1
        left += 1

    answer = max(answer, right - left + 1)

print(answer)
```

## 오늘의 회고(실수한 점 포함)

원소별 등장 횟수를 딕셔너리에 저장하고 두 포인터로 연속 구간을 관리한다는 핵심 접근은 맞았다. 다만 윈도우를 어느 시점에 유효하다고 볼 것인지와 길이 계산에서 수정할 부분이 있었다.

1. **포인터가 표현하는 구간을 먼저 정의해야 한다.**

   `[left, right]`처럼 양 끝을 포함하면 길이는 `right - left + 1`이다. `[left, right)`처럼 오른쪽을 포함하지 않으면 `right - left`다. 두 표현을 섞으면 오프바이원 오류가 발생한다.

2. **조건을 만족하는 상태에서만 정답을 갱신해야 한다.**

   새 원소를 추가한 직후에는 등장 횟수가 `K`를 초과할 수 있다. `left`를 이동해 위반을 해소한 다음 길이를 계산해야 한다.

3. **전체 상태가 아니라 방금 바뀐 상태를 확인할 수 있다.**

   새로 추가된 숫자의 빈도만 증가했으므로 그 숫자의 개수만 검사하면 된다. `max(count.values())`는 불필요한 전체 탐색이다.

4. **N = 1 같은 최소 입력을 확인해야 한다.**

   `right = 1`에서 시작하면 길이 1인 입력을 처리할 수 없다. `for right in range(N)`을 사용하면 첫 원소부터 자연스럽게 확인할 수 있다.

5. **모든 길이 후보를 저장할 필요가 없다.**

   정답은 최대 길이 하나이므로 `answer` 정수 변수를 즉시 갱신하면 된다. 후보 리스트는 메모리를 더 사용하고 빈 리스트 예외도 만들 수 있다.

6. **딕셔너리는 현재 윈도우의 상태와 항상 일치해야 한다.**

   오른쪽 원소가 들어올 때 증가시키고, 왼쪽 원소가 빠질 때 감소시킨다. 포인터 이동과 빈도 갱신은 반드시 함께 이뤄져야 한다.

이번 문제를 통해 슬라이딩 윈도우에서는 **구간 확장 → 조건 위반 해소 → 유효한 길이 갱신** 순서를 일정하게 유지해야 한다는 점을 복기했다. 또한 입력 제한이 큰 문제에서는 코드 한 줄인 `max()`도 내부적으로 전체 자료구조를 순회할 수 있다는 점까지 시간복잡도에 포함해야 한다.
