## 문제 정의

[백준 3273번 두 수의 합](https://www.acmicpc.net/problem/3273)은 서로 다른 양의 정수로 이루어진 수열에서 두 수의 합이 `X`가 되는 쌍의 개수를 구하는 문제다.

수열의 두 원소 `a[i]`, `a[j]`에 대해 다음 조건을 만족하는 쌍을 찾아야 한다.

```text
a[i] + a[j] = X
1 <= i < j <= N
```

주요 제한은 다음과 같다.

- 수열의 크기 `N`은 최대 100,000이다.
- 각 원소는 1 이상 1,000,000 이하인 서로 다른 양의 정수다.
- 목표 합 `X`는 1 이상 2,000,000 이하이다.

예제는 다음과 같다.

```text
numbers = [5, 12, 7, 10, 9, 1, 2, 3, 11]
X = 13
```

합이 13인 쌍은 `(1, 12)`, `(2, 11)`, `(3, 10)`이므로 정답은 3이다.

## 접근 및 설계

처음 입력된 수열은 정렬되어 있지 않다. 두 포인터가 가리키는 값의 합을 보고 어느 포인터를 이동할지 결정하려면 값의 대소 관계가 보장되어야 하므로 먼저 오름차순으로 정렬한다.

```python
numbers.sort()
```

정렬한 수열의 양 끝에 포인터를 배치한다.

```python
left = 0
right = N - 1
```

- `left`는 현재 범위에서 가장 작은 값을 가리킨다.
- `right`는 현재 범위에서 가장 큰 값을 가리킨다.

두 값의 합 `temp`와 목표값 `X`를 비교해 포인터를 이동한다.

### 합이 X보다 작은 경우

```python
if temp < X:
    left += 1
```

현재 합을 더 크게 만들어야 한다. 정렬된 수열에서 `right`를 왼쪽으로 옮기면 값이 작아지므로 도움이 되지 않는다. 더 작은 값을 가리키는 `left`를 오른쪽으로 옮겨 합을 증가시킨다.

### 합이 X보다 큰 경우

```python
elif temp > X:
    right -= 1
```

현재 합을 더 작게 만들어야 한다. `left`를 오른쪽으로 옮기면 값이 커지므로, 큰 값을 가리키는 `right`를 왼쪽으로 옮긴다.

### 합이 X와 같은 경우

```python
else:
    answer += 1
    left += 1
    right -= 1
```

조건을 만족하는 쌍을 찾았으므로 정답을 1 증가시킨다. 문제에서 수열의 모든 수가 서로 다르다고 했으므로 현재 `numbers[left]`와 짝을 이루는 값은 `X - numbers[left]` 하나뿐이다. 현재 `numbers[right]`의 짝도 마찬가지다.

따라서 현재 쌍을 센 다음 두 포인터를 동시에 이동해도 정답이 될 다른 쌍을 놓치지 않는다.

### 왜 모든 조합을 확인하지 않아도 되는가

정렬된 배열에서 현재 합이 `X`보다 작다고 하자.

```text
numbers[left] + numbers[right] < X
```

`numbers[right]`는 현재 범위에서 가장 큰 값이다. `left`를 그대로 둔 채 `right`를 더 작은 값으로 바꾸면 합은 더 작아질 뿐이므로 `numbers[left]`로 만들 수 있는 정답 쌍은 없다. 따라서 `left`를 안전하게 한 칸 이동할 수 있다.

합이 `X`보다 큰 경우도 반대 논리로 현재 `numbers[right]`와 정답을 만들 수 있는 더 큰 왼쪽 값은 없으므로 `right`를 이동할 수 있다.

## 사용한 자료구조

### 리스트(List)

입력된 수열을 Python 리스트에 저장한다.

```python
numbers = list(map(int, input().split()))
```

리스트는 인덱스로 양 끝 원소에 바로 접근할 수 있고, `sort()`를 이용해 제자리 정렬할 수 있어 투 포인터를 적용하기 적합하다.

### 두 개의 인덱스 포인터

별도의 큐나 스택을 만들지 않고 정수형 인덱스 두 개로 현재 탐색 범위를 표현한다.

```python
left = 0
right = N - 1
```

포인터는 한 방향으로만 이동한다.

- `left`: 오른쪽으로 이동
- `right`: 왼쪽으로 이동

이미 후보에서 제외한 원소를 다시 검사하지 않으므로 선형 탐색이 가능하다.

### 누적 정답 변수

합이 `X`인 쌍을 발견할 때마다 `answer`를 1 증가시킨다. 실제 쌍을 저장할 필요가 없으므로 개수만 유지한다.

## 사용한 알고리즘

### 정렬

투 포인터를 움직일 근거를 만들기 위해 수열을 오름차순으로 정렬한다.

```text
입력:  5 12 7 10 9 1 2 3 11
정렬:  1 2 3 5 7 9 10 11 12
```

정렬하지 않은 상태에서는 합이 작을 때 어떤 원소를 바꿔야 합이 커지는지 판단할 수 없다. 정렬은 투 포인터 탐색이 성립하게 만드는 전처리다.

### 투 포인터(Two Pointer)

정렬된 배열의 양 끝에서 시작해 두 값의 합에 따라 탐색 범위를 줄인다.

```python
while left < right:
    temp = numbers[left] + numbers[right]

    if temp < X:
        left += 1
    elif temp > X:
        right -= 1
    else:
        answer += 1
        left += 1
        right -= 1
```

`left < right`인 동안만 반복하는 이유는 서로 다른 두 원소를 선택해야 하기 때문이다. 두 포인터가 같은 위치를 가리키면 하나의 원소를 두 번 사용하는 셈이므로 탐색을 종료한다.

### 예제 탐색 과정

```text
정렬된 수열: [1, 2, 3, 5, 7, 9, 10, 11, 12]
X = 13

left=1, right=12 -> 합 13 -> 정답, 양쪽 이동
left=2, right=11 -> 합 13 -> 정답, 양쪽 이동
left=3, right=10 -> 합 13 -> 정답, 양쪽 이동
left=5, right=9  -> 합 14 -> right 이동
left=5, right=7  -> 합 12 -> left 이동

포인터 교차 -> 탐색 종료
answer = 3
```

### 완전 탐색과의 비교

두 수를 선택하는 모든 조합을 이중 반복문으로 검사하면 약 `N(N-1)/2`개의 쌍을 확인해야 한다.

`N = 100,000`이면 조합 수가 약 50억 개이므로 `O(N²)` 완전 탐색은 사용할 수 없다. 정렬과 투 포인터를 결합하면 정렬 이후의 쌍 탐색을 `O(N)`에 끝낼 수 있다.

## 시간복잡도

수열의 크기를 `N`이라고 하자.

- 입력 리스트 생성: `O(N)`
- 리스트 정렬: `O(N log N)`
- 투 포인터 탐색: `O(N)`
- 전체 시간복잡도: **`O(N log N)`**
- 입력 리스트를 포함한 공간복잡도: **`O(N)`**

투 포인터 탐색 중 `left`는 최대 `N - 1`번 증가하고 `right`도 최대 `N - 1`번 감소한다. 반복문 안에서 포인터가 되돌아가지 않으므로 탐색 자체는 `O(N)`이다.

전체 수행 시간은 정렬의 `O(N log N)`이 지배한다. `N`이 최대 100,000인 조건에서 충분히 처리할 수 있다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[N, 수열, X 입력]
          |
          v
[수열을 오름차순 정렬]
          |
          v
[left = 0, right = N - 1]
          |
          v
      [left < right?] -- No --> [answer 출력]
          |
         Yes
          |
          v
[temp = numbers[left] + numbers[right]]
          |
          v
     [temp와 X 비교]
       /     |      \
  temp<X   temp=X   temp>X
     |        |        |
     v        v        v
[left++] [answer++] [right--]
          [left++]
          [right--]
     \        |        /
      \       |       /
       [다음 범위 확인]
              |
              v
       [left < right?]
```

## 최종 제출 코드

```python
import sys

input = sys.stdin.readline

N = int(input())
numbers = list(map(int, input().split()))
X = int(input())

numbers.sort()

left = 0
right = N - 1
answer = 0

while left < right:
    temp = numbers[left] + numbers[right]

    if temp < X:
        left += 1
    elif temp > X:
        right -= 1
    else:
        answer += 1
        left += 1
        right -= 1

print(answer)
```

## 오늘의 회고(실수한 점 포함)

이번 문제에서는 정렬한 수열의 양 끝에서 시작하는 투 포인터를 정확하게 적용했다. 별도의 오답 수정 없이 문제 조건에 맞는 풀이를 구성했으며, 복기할 핵심은 다음과 같다.

1. **정렬은 단순한 전처리가 아니라 포인터 이동의 근거다.**

   합이 작을 때 `left`를 이동하고 합이 클 때 `right`를 이동해도 되는 이유는 수열이 오름차순으로 정렬되어 있기 때문이다.

2. **완전 탐색의 복잡도를 먼저 계산했다면 투 포인터의 필요성이 보인다.**

   `N`이 최대 100,000이므로 이중 반복문의 `O(N²)`은 약 50억 개의 쌍을 확인하게 된다. 입력 제한을 보고 더 작은 탐색 방법을 찾아야 한다.

3. **정답을 찾았을 때 두 포인터를 모두 이동한 처리가 정확하다.**

   모든 원소가 서로 다르므로 현재 왼쪽 값과 합이 `X`가 되는 오른쪽 값은 하나뿐이다. 이미 센 두 값을 다시 후보로 둘 필요가 없다.

4. **반복 조건은 `left <= right`가 아니라 `left < right`다.**

   같은 인덱스의 원소를 두 번 더하면 안 되므로 두 포인터가 만나는 순간 탐색을 종료해야 한다.

5. **알고리즘 전체 복잡도에는 정렬도 포함해야 한다.**

   투 포인터 부분만 보면 `O(N)`이지만 정렬에 `O(N log N)`이 필요하므로 전체 시간복잡도는 `O(N log N)`이다.

이번 문제를 통해 **정렬된 배열에서 두 원소의 합을 찾을 때, 합이 작으면 왼쪽 포인터를 키우고 합이 크면 오른쪽 포인터를 줄이는 투 포인터 패턴**을 복기했다. 앞으로 두 수의 합, 구간 합, 연속 부분 수열처럼 탐색 범위를 한 방향으로 줄일 수 있는 문제에서는 투 포인터 적용 가능성을 먼저 확인해야겠다.
