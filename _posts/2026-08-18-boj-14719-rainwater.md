## 문제 정의

[백준 14719번 빗물](https://www.acmicpc.net/problem/14719)은 2차원 세계에 쌓인 블록의 높이가 왼쪽부터 주어질 때, 비가 충분히 내린 뒤 블록 사이에 고이는 빗물의 총량을 구하는 문제다.

각 가로 위치에는 바닥부터 블록이 연속해서 쌓여 있으므로 내부에 빈 공간은 없다. 물은 왼쪽과 오른쪽이 모두 블록으로 막힌 위치에만 고일 수 있다.

```text
블록 높이: 3 0 1 4

두 번째 열에 고이는 물: 3
세 번째 열에 고이는 물: 2
총 빗물: 5
```

각 위치에 고일 수 있는 물의 높이는 왼쪽에서 가장 높은 벽과 오른쪽에서 가장 높은 벽 중 더 낮은 높이에 의해 결정된다.

## 접근 및 설계

작성한 코드는 양 끝 열을 제외한 각 위치를 하나씩 확인한다.

```python
for i in range(1, W - 1):
```

현재 위치의 왼쪽에서 가장 높은 블록과 오른쪽에서 가장 높은 블록을 찾는다.

```python
left_max = max(rain[:i])
right_max = max(rain[i + 1:])
```

두 벽 중 낮은 쪽이 현재 위치의 수면 높이가 된다.

```python
water_height = min(left_max, right_max)
```

수면 높이가 현재 블록보다 높다면 그 차이만큼 물이 고인다.

```python
if water_height > rain[i]:
    answer += water_height - rain[i]
```

이 방식으로 각 열에 고이는 물을 독립적으로 계산한 뒤 모두 더하면 전체 빗물의 양을 구할 수 있다.

### 왜 두 벽 중 낮은 높이를 사용하는가

현재 열의 왼쪽 최고 높이를 `left_max`, 오른쪽 최고 높이를 `right_max`라고 하자.

왼쪽 벽이 아무리 높아도 오른쪽 벽이 낮으면 물은 오른쪽 벽보다 높게 고일 수 없다. 반대의 경우도 마찬가지다. 따라서 물을 가둘 수 있는 실제 높이는 두 값 중 작은 값이다.

```text
왼쪽 최고 벽: 5
오른쪽 최고 벽: 3

수면 높이: min(5, 3) = 3
```

현재 블록 높이가 `1`이라면 해당 열에 고이는 물은 `3 - 1 = 2`다.

이를 식으로 표현하면 다음과 같다.

```text
현재 열의 빗물
= max(0, min(왼쪽 최고 높이, 오른쪽 최고 높이) - 현재 높이)
```

작성한 코드에서는 수면 높이가 현재 높이보다 큰지 먼저 검사해 `max(0, ...)`과 같은 역할을 한다.

### 예제 흐름

```text
H = 4, W = 4
rain = [3, 0, 1, 4]
```

양 끝을 제외한 인덱스 `1`, `2`를 확인한다.

```text
[인덱스 1]
현재 높이: 0
왼쪽 최고 높이: max([3]) = 3
오른쪽 최고 높이: max([1, 4]) = 4
수면 높이: min(3, 4) = 3
고이는 물: 3 - 0 = 3

[인덱스 2]
현재 높이: 1
왼쪽 최고 높이: max([3, 0]) = 3
오른쪽 최고 높이: max([4]) = 4
수면 높이: min(3, 4) = 3
고이는 물: 3 - 1 = 2

총 빗물: 3 + 2 = 5
```

### 양 끝 열을 확인하지 않는 이유

첫 번째 열은 왼쪽에 벽이 없고 마지막 열은 오른쪽에 벽이 없다. 한쪽이 열려 있으므로 물을 가둘 수 없다.

따라서 다음 범위만 순회한다.

```python
range(1, W - 1)
```

`W`가 1이나 2여도 이 범위는 비어 있으므로 별도의 예외 처리 없이 정답 `0`을 출력한다.

### 세로 길이 `H`를 계산에 사용하지 않는 이유

입력으로 받은 `H`는 세계의 최대 세로 크기이며 각 블록 높이가 유효한지 제한하는 값이다. 실제 지형 모양은 두 번째 줄의 `rain`에 모두 들어 있다.

열별로 고이는 물은 블록 높이들의 상대적인 차이만으로 계산할 수 있으므로 풀이 과정에서 `H`를 직접 사용할 필요는 없다. 입력 형식을 맞추기 위해 값을 읽되 계산에는 `W`와 `rain`을 사용한다.

## 사용한 자료구조

### 리스트(List)

각 가로 위치의 블록 높이를 `rain` 리스트에 저장한다.

```python
rain = list(map(int, input().split()))
```

인덱스 `i`가 곧 가로 위치이고 `rain[i]`가 해당 열의 블록 높이다.

왼쪽과 오른쪽 구간은 리스트 슬라이싱으로 만든다.

```python
rain[:i]
rain[i + 1:]
```

코드가 직관적이라는 장점이 있지만 Python 리스트 슬라이싱은 원소를 복사해 새 리스트를 만든다는 점을 복잡도 계산에 포함해야 한다.

### 누적 정답 변수

각 열에 고인 물을 `answer`에 바로 더한다.

```python
answer += water_height - rain[i]
```

열별 물의 양을 별도 리스트에 저장할 필요가 없으므로 합계 변수 하나만 유지한다.

## 사용한 알고리즘

### 열별 시뮬레이션

각 열을 기준으로 왼쪽과 오른쪽의 최고 벽을 찾고 물이 고일 수 있는 높이를 계산한다.

```python
for i in range(1, W - 1):
    left_max = max(rain[:i])
    right_max = max(rain[i + 1:])
    water_height = min(left_max, right_max)

    if water_height > rain[i]:
        answer += water_height - rain[i]
```

격자를 행 단위로 직접 그리거나 빈 칸마다 물인지 검사하지 않고, 각 열에서 물이 차는 세로 길이를 한 번에 계산한다.

### 좌우 최댓값

현재 위치의 물 높이를 결정하는 데 필요한 정보는 다음 두 개뿐이다.

- 현재 위치 왼쪽의 최고 블록 높이
- 현재 위치 오른쪽의 최고 블록 높이

가장 가까운 벽이 아니라 가장 높은 벽을 찾는 이유는 중간에 낮은 벽이 있어도 더 바깥의 높은 벽까지 물이 이어질 수 있기 때문이다.

### 입력이 더 크다면 `O(W)`로 개선할 수 있다

현재 코드는 각 위치에서 왼쪽과 오른쪽을 다시 탐색한다. 이 문제에서는 `W`가 최대 500이라 충분하지만, 폭이 매우 큰 문제라면 각 방향의 누적 최댓값을 미리 계산할 수 있다.

```python
left_max = [0] * W
right_max = [0] * W

left_max[0] = rain[0]
for i in range(1, W):
    left_max[i] = max(left_max[i - 1], rain[i])

right_max[-1] = rain[-1]
for i in range(W - 2, -1, -1):
    right_max[i] = max(right_max[i + 1], rain[i])

answer = 0
for i in range(W):
    answer += min(left_max[i], right_max[i]) - rain[i]
```

왼쪽과 오른쪽을 각각 한 번씩만 순회하므로 시간복잡도를 `O(W)`로 줄일 수 있다. 추가 배열 두 개 때문에 공간복잡도는 `O(W)`다.

## 시간복잡도

가로 길이를 `W`라고 하자.

### 작성한 풀이

- 확인할 열의 개수: `O(W)`
- 각 열에서 왼쪽 슬라이스 생성 및 최댓값 탐색: `O(W)`
- 각 열에서 오른쪽 슬라이스 생성 및 최댓값 탐색: `O(W)`
- 전체 시간복잡도: **`O(W²)`**
- 입력 리스트를 포함한 공간복잡도: **`O(W)`**
- 슬라이싱으로 생성되는 임시 리스트의 최대 크기: **`O(W)`**

`W`가 최대 500이므로 최악의 경우에도 약 25만 단위의 높이 확인으로 충분히 처리할 수 있다.

### 누적 최댓값 개선 풀이

- 왼쪽 누적 최댓값 계산: `O(W)`
- 오른쪽 누적 최댓값 계산: `O(W)`
- 열별 빗물 계산: `O(W)`
- 전체 시간복잡도: **`O(W)`**
- 공간복잡도: **`O(W)`**

## 최종 제출 코드

```python
import sys

input = sys.stdin.readline

H, W = map(int, input().split())
rain = list(map(int, input().split()))

answer = 0

for i in range(1, W - 1):
    left_max = max(rain[:i])
    right_max = max(rain[i + 1:])
    water_height = min(left_max, right_max)

    if water_height > rain[i]:
        answer += water_height - rain[i]

print(answer)
```

## 오늘의 회고(실수한 점 포함)

각 열에 물이 고이려면 왼쪽과 오른쪽에 모두 벽이 있어야 하고, 두 벽 중 낮은 높이까지만 물이 찬다는 핵심 조건을 코드로 정확하게 옮겼다.

이번 풀이는 별도의 오답 수정 없이 문제 제한을 통과할 수 있는 접근이다. 복기할 부분은 다음과 같다.

1. **전체 그림을 열 단위 문제로 분해했다.**

   물의 모양을 한 번에 시뮬레이션하려고 하면 복잡해 보이지만 각 열에 고이는 높이를 독립적으로 계산하면 단순한 최댓값 문제로 바뀐다.

2. **현재 블록보다 수면이 높을 때만 더했다.**

   현재 블록이 양쪽 벽 중 낮은 벽보다 높다면 물이 고이지 않는다. 음수 값을 더하지 않도록 조건을 둔 것이 정확하다.

3. **양 끝은 물을 가둘 수 없다.**

   한쪽 벽이 없는 첫 열과 마지막 열을 순회 범위에서 제외해 빈 슬라이스에 `max()`를 호출하는 문제도 피했다.

4. **슬라이싱의 비용을 놓치기 쉽다.**

   `rain[:i]`와 `rain[i + 1:]`는 보기에는 간단하지만 매번 새 리스트를 만든다. 현재 제한에서는 충분하지만 시간복잡도는 `O(W)`가 아니라 `O(W²)`다.

5. **제한에 맞는 복잡도인지 먼저 판단해야 한다.**

   `W ≤ 500`이므로 현재 풀이가 실용적이다. 모든 문제에서 무조건 가장 복잡한 최적화를 구현할 필요는 없지만, 입력 제한이 커질 때 사용할 `O(W)` 누적 최댓값이나 투 포인터 풀이도 함께 알아두는 것이 좋다.

6. **입력값이 계산에 직접 쓰이지 않을 수도 있다.**

   `H`는 지형의 최대 높이를 나타내지만 실제 빗물 계산은 `rain`의 높이 차이만으로 가능하다. 사용하지 않는 입력이 있어도 문제 조건상 필요한 값인지, 계산에 정말 필요한 상태인지 구분해야 한다.

이번 문제를 통해 특정 위치에 쌓이는 양이 양쪽 경계에 의해 결정되는 문제에서는 **왼쪽 최댓값과 오른쪽 최댓값 중 작은 값을 기준으로 현재 높이와의 차이를 계산하는 방식**을 복기했다. 또한 코드 한 줄에 포함된 슬라이싱과 `max()`의 내부 비용까지 고려해 시간복잡도를 계산해야 한다는 점을 확인했다.
