## 문제 정의

[백준 1931번 회의실 배정](https://www.acmicpc.net/problem/1931)은 하나의 회의실을 사용하려는 `N`개 회의의 시작 시각과 종료 시각이 주어질 때, 서로 겹치지 않게 배정할 수 있는 회의의 최대 개수를 구하는 문제다.

한 회의가 끝나는 시각과 다음 회의가 시작하는 시각이 같아도 두 회의를 연속해서 진행할 수 있다. 또한 시작 시각과 종료 시각이 같은, 즉 회의 시간이 0인 경우도 존재한다.

핵심은 단순히 입력된 순서대로 가능한 회의를 선택하는 것이 아니라, 앞으로 더 많은 회의를 배정할 수 있도록 **가장 빨리 끝나는 회의를 먼저 선택하는 것**이다.

## 접근 및 설계

### 1차 풀이: 입력 순서대로 회의 선택

처음에는 첫 번째로 입력된 회의를 선택한 뒤, 이후 입력 중 현재 회의가 끝난 다음 시작하는 회의를 선택했다.

```python
curr_start, curr_finish = map(int, input().split())
count = 1

for _ in range(N - 1):
    start_time, finish_time = map(int, input().split())

    if start_time > curr_finish:
        curr_start = start_time
        curr_finish = finish_time
        count += 1
```

하지만 문제의 입력은 회의가 시간순으로 정렬되어 있다는 보장이 없다. 따라서 첫 번째 입력을 무조건 선택하면 너무 늦게 끝나는 회의를 먼저 고를 수 있다.

```text
3
4 5
1 2
2 3
```

입력 순서대로 보면 `(4, 5)`를 먼저 선택해 결과가 1이 된다. 하지만 종료 시각을 기준으로 정렬하면 `(1, 2) -> (2, 3) -> (4, 5)`를 모두 선택할 수 있으므로 정답은 3이다.

조건식에도 문제가 있었다.

```python
if start_time > curr_finish:
```

회의가 끝나는 동시에 다음 회의를 시작할 수 있으므로 `>`가 아니라 `>=`를 사용해야 한다. 예를 들어 `(1, 2)` 다음에 `(2, 3)`을 배정하는 것은 가능하다.

### 2차 풀이: 종료 시각을 기준으로 정렬

수정한 코드에서는 모든 회의를 리스트에 저장한 뒤 종료 시각이 빠른 순서로 정렬했다. 종료 시각이 같으면 시작 시각이 빠른 회의를 먼저 배치했다.

```python
time.sort(key=lambda x: (x[1], x[0]))
```

정렬이 끝나면 다음 과정을 반복한다.

1. 아직 선택한 회의와 겹치지 않는지 확인한다.
2. 현재 회의의 시작 시각이 마지막으로 선택한 회의의 종료 시각보다 크거나 같으면 선택한다.
3. 마지막 종료 시각을 현재 회의의 종료 시각으로 갱신한다.

```python
if start_time >= curr_finish:
    curr_finish = finish_time
    count += 1
```

종료 시각이 같은 경우 시작 시각까지 오름차순으로 정렬하는 이유는 회의 시간이 0인 경우 때문이다.

```text
(0, 1), (1, 1)
```

두 회의는 모두 종료 시각이 1이다. `(0, 1)`을 먼저 확인하면 이어서 `(1, 1)`까지 선택할 수 있다. 따라서 정렬 기준을 `(종료 시각, 시작 시각)`으로 명시하는 것이 안전하다.

### 왜 가장 빨리 끝나는 회의를 선택하는가

현재 선택할 수 있는 회의 중 가장 빨리 끝나는 회의를 고르면 그 뒤에 남는 시간이 가장 길어진다. 남은 시간이 길수록 이후 회의를 배정할 기회가 줄어들지 않는다.

어떤 최적해가 첫 회의로 더 늦게 끝나는 회의를 선택했다고 가정하자. 그 회의를 가장 빨리 끝나는 회의로 바꾸더라도 이후 회의들의 시작 시각보다 더 일찍 또는 같은 시각에 끝난다. 따라서 기존에 배정했던 나머지 회의를 그대로 이어 붙일 수 있고, 전체 회의 수는 감소하지 않는다.

이 교환 과정을 반복하면 가장 빨리 끝나는 회의를 순서대로 선택하는 그리디 결과도 최적해가 된다.

## 사용한 자료구조

### 리스트(List)

각 회의를 `[시작 시각, 종료 시각]` 형태로 리스트에 저장했다.

```python
meetings = []

for _ in range(N):
    meetings.append(tuple(map(int, input().split())))
```

입력 순서와 관계없이 전체 회의를 정렬해야 하므로 `N`개의 회의를 메모리에 저장한다. 회의를 읽은 뒤 값 자체를 수정할 필요가 없기 때문에 최종 코드에서는 각 회의를 튜플로 표현했다.

### 상태 변수

모든 선택 결과를 별도의 리스트에 저장할 필요는 없다. 다음 회의를 선택할 수 있는지는 마지막으로 선택한 회의의 종료 시각만 있으면 판단할 수 있다.

- `last_end`: 마지막으로 선택한 회의의 종료 시각
- `count`: 지금까지 선택한 회의의 개수

처음 코드의 `curr_start`는 값을 갱신하지만 이후 조건에서 사용하지 않는다. 최종 코드에서는 불필요한 상태를 제거하고 `last_end`만 유지했다.

## 사용한 알고리즘

### 정렬(Sorting)

회의를 다음 우선순위로 오름차순 정렬한다.

1. 종료 시각이 빠른 회의
2. 종료 시각이 같다면 시작 시각이 빠른 회의

```python
meetings.sort(key=lambda meeting: (meeting[1], meeting[0]))
```

시작 시각만 빠른 회의나 회의 시간이 짧은 회의를 먼저 선택하는 것으로는 최적해를 보장할 수 없다. 중요한 기준은 다음 회의를 위해 회의실을 가장 일찍 비워 주는 **종료 시각**이다.

### 그리디(Greedy)

정렬된 회의를 앞에서부터 확인하며 현재 선택 가능한 회의라면 바로 선택한다.

```python
for start, end in meetings:
    if start >= last_end:
        count += 1
        last_end = end
```

각 단계에서 가장 빨리 끝나는 회의를 선택한다는 지역 최적 선택이 이후에 사용할 수 있는 시간을 가장 많이 남기므로 전체 회의 수도 최대가 된다.

## 시간복잡도

- 회의 `N`개 입력 및 저장: `O(N)`
- `(종료 시각, 시작 시각)` 기준 정렬: `O(N log N)`
- 정렬된 회의를 한 번 순회: `O(N)`
- 전체 시간복잡도: **`O(N log N)`**
- 공간복잡도: **`O(N)`**

전체 실행 시간은 정렬 단계가 지배한다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[N개의 회의 입력]
          |
          v
[(종료 시각, 시작 시각) 오름차순 정렬]
          |
          v
[last_end = 0, count = 0]
          |
          v
[정렬된 회의를 앞에서부터 하나씩 확인]
          |
          v
[시작 시각 >= last_end 인가?]
       /                 \
     Yes                  No
      |                    |
      v                    v
[회의 선택]             [회의 건너뜀]
[count += 1]                |
[last_end = 종료 시각]      |
       \                   /
        v                 v
          [다음 회의 확인]
                  |
                  v
          [모든 회의 확인 완료]
                  |
                  v
              [count 출력]
```

## 최종 제출 코드

```python
import sys

input = sys.stdin.readline

N = int(input())
meetings = []

for _ in range(N):
    meetings.append(tuple(map(int, input().split())))

meetings.sort(key=lambda meeting: (meeting[1], meeting[0]))

last_end = 0
count = 0

for start, end in meetings:
    if start >= last_end:
        last_end = end
        count += 1

print(count)
```

## 오늘의 회고(실수한 점 포함)

처음 풀이에서는 현재 회의 이후에 시작하는 회의를 하나씩 선택한다는 방향만 생각했고, **어떤 회의를 먼저 선택해야 전체 개수가 최대가 되는지**를 고려하지 못했다.

이번 풀이에서 수정한 부분은 다음과 같다.

1. **입력 순서를 그대로 사용했다.**

   입력이 시간순이라는 조건은 없다. 첫 입력을 무조건 선택하면 늦게 끝나는 회의가 기준이 되어 더 많은 회의를 놓칠 수 있다. 그리디 문제에서는 반복문을 작성하기 전에 선택 순서를 만드는 정렬 기준부터 찾아야 한다.

2. **연속해서 진행할 수 있는 회의를 제외했다.**

   `start_time > curr_finish`를 사용하면 이전 회의의 종료 시각과 다음 회의의 시작 시각이 같은 경우를 선택하지 못한다. 문제의 “회의가 끝나는 것과 동시에 다음 회의가 시작될 수 있다”는 조건을 코드의 `>=`에 정확히 반영해야 한다.

3. **왜 종료 시각 기준인지 근거가 부족했다.**

   단순히 유명한 정렬 패턴을 외우는 것보다, 가장 빨리 끝나는 회의를 선택하면 남은 시간이 최대가 되고 교환 논증으로 최적해를 보장한다는 이유까지 설명할 수 있어야 비슷한 구간 스케줄링 문제에도 적용할 수 있다.

4. **사용하지 않는 상태를 유지했다.**

   `curr_start`는 선택할 때마다 갱신했지만 실제 판단에는 사용되지 않았다. 다음 선택에 필요한 값은 마지막 종료 시각 하나뿐이다. 필요한 상태만 남기면 코드와 정당성을 함께 설명하기 쉬워진다.

이번 문제를 통해 구간을 최대한 많이 선택하는 문제에서는 **종료 시각이 빠른 순서로 정렬한 뒤, 직전 종료 시각과 겹치지 않는 구간을 선택하는 그리디 전략**을 우선 검토해야 한다는 점을 복기했다. 또한 비교 연산자의 경계값과 입력 정렬 여부를 문제 조건에서 반드시 확인해야 한다.
