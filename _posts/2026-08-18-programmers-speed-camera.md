## 문제 정의

[프로그래머스 단속카메라](https://school.programmers.co.kr/learn/courses/30/lessons/42884)는 각 차량의 고속도로 진입 지점과 진출 지점이 주어질 때, 모든 차량이 최소 한 번 카메라를 만나도록 설치해야 하는 카메라의 최소 개수를 구하는 문제다.

각 차량 경로는 닫힌 구간 `[진입 지점, 진출 지점]`으로 볼 수 있다. 카메라가 진입 지점이나 진출 지점에 정확히 설치되어 있어도 해당 차량은 카메라를 만난 것으로 처리한다.

```text
차량 A: [-20, -15]
차량 B: [-18, -13]

-15에 카메라 설치
-> A와 B를 모두 단속할 수 있음
```

결국 모든 구간을 최소 개수의 점으로 찌르는 구간 커버 문제다. 서로 겹치는 차량 경로들은 카메라 하나로 함께 단속할 수 있다.

## 접근 및 설계

작성한 코드는 차량 경로를 진출 지점 오름차순으로 정렬했다.

```python
routes.sort(key=lambda x: x[1])
```

그다음 가장 빨리 고속도로를 빠져나가는 첫 차량의 진출 지점에 카메라를 설치했다.

```python
camera = routes[0][1]
answer = 1
```

이후 차량의 진입 지점이 현재 카메라 위치보다 작거나 같으면 이미 해당 카메라를 만나므로 추가 설치를 하지 않는다.

```python
if routes[i][0] <= camera:
    continue
```

현재 카메라보다 뒤에서 진입하는 차량은 기존 카메라를 만날 수 없다. 이 경우 해당 차량의 진출 지점에 새 카메라를 설치한다.

```python
camera = routes[i][1]
answer += 1
```

이 풀이는 문제의 정답 그리디 전략을 정확하게 구현했다.

### 왜 진출 지점을 기준으로 정렬하는가

가장 빨리 진출하는 차량은 해당 진출 지점을 지나면 더 이상 단속할 수 없다. 따라서 아직 단속되지 않은 차량 중 진출 지점이 가장 빠른 차량을 먼저 처리해야 한다.

그 차량의 경로 안에서 카메라를 최대한 오른쪽인 진출 지점에 설치하면 현재 차량을 단속하면서 이후 차량과 겹칠 가능성을 가장 크게 남길 수 있다.

```text
현재 차량: [1, 5]

1에 설치: 현재 차량은 단속하지만 이후 구간과 겹칠 기회가 적음
5에 설치: 현재 차량을 단속하면서 뒤쪽 차량도 함께 단속할 가능성이 큼
```

진입 지점만 기준으로 정렬해 가장 먼저 진입한 차량부터 처리하면 그 차량의 어느 위치에 카메라를 놓아야 뒤 차량을 많이 포함하는지 바로 결정하기 어렵다. 반면 가장 빠른 진출 지점은 현재 반드시 처리해야 하는 기한이자 안전하게 선택할 수 있는 가장 오른쪽 위치다.

### 왜 진입 지점만 비교해도 되는가

현재 코드의 단속 여부 확인은 다음 조건 하나다.

```python
routes[i][0] <= camera
```

일반적으로 점이 구간 안에 있는지 확인하려면 다음 두 조건이 모두 필요해 보인다.

```text
진입 지점 <= 카메라 <= 진출 지점
```

하지만 차량들을 진출 지점 오름차순으로 정렬했다. 현재 `camera`는 앞서 처리한 어떤 차량의 진출 지점이고, 이후 차량의 진출 지점은 그 위치보다 크거나 같다.

```text
camera <= 현재 차량의 진출 지점
```

오른쪽 경계 조건은 정렬에 의해 이미 보장된다. 따라서 현재 차량의 진입 지점이 `camera`보다 작거나 같은지만 확인하면 카메라가 구간 안에 있다는 것을 알 수 있다.

### 경계에서 `<=`를 사용하는 이유

차량이 카메라가 설치된 지점에서 진입하거나 진출해도 단속된 것으로 인정한다.

```text
camera = -5
route = [-5, -3]
```

이 차량은 진입과 동시에 카메라를 만나므로 새 카메라가 필요 없다. 따라서 조건은 `<`가 아니라 `<=`여야 한다.

### 공식 예제 흐름

```text
routes = [[-20,-15], [-14,-5], [-18,-13], [-5,-3]]
```

진출 지점 기준으로 정렬하면 다음과 같다.

```text
[-20, -15]
[-18, -13]
[-14,  -5]
[ -5,  -3]
```

```text
첫 카메라: -15

[-20, -15] -> -15를 포함하므로 단속
[-18, -13] -> -15를 포함하므로 단속
[-14,  -5] -> 진입 지점 -14 > -15, 기존 카메라로 단속 불가
               새 카메라를 -5에 설치
[ -5,  -3] -> -5를 포함하므로 단속

필요한 카메라: 2대
```

### 그리디 선택이 최적인 이유

아직 단속되지 않은 차량 중 가장 빨리 진출하는 차량의 경로를 `[start, end]`라고 하자. 어떤 최적해도 이 차량을 단속하기 위해 `[start, end]` 안에 카메라 하나를 설치해야 한다.

최적해가 해당 카메라를 `x`에 설치했다고 가정하면 `x <= end`다. 이 카메라를 `end`로 옮겨도 현재 차량은 여전히 단속된다.

또한 진출 지점순으로 처리하고 있으므로 남은 다른 차량들의 진출 지점은 모두 `end`보다 크거나 같다. 다른 차량이 기존 위치 `x`를 포함했다면 그 차량의 진입 지점은 `x`보다 작거나 같고, `end`는 `x`보다 오른쪽이면서 그 차량의 진출 지점 이하다. 따라서 `end`도 해당 차량 경로 안에 있다.

즉 가장 빠른 진출 지점으로 카메라를 옮겨도 단속 가능한 차량을 잃지 않는다. 이 선택을 반복하면 현재 그리디 결과와 같은 최적해를 만들 수 있다.

## 사용한 자료구조

### 리스트(List)

`routes`는 각 차량의 `[진입 지점, 진출 지점]`을 담은 2차원 리스트다.

```python
routes.sort(key=lambda route: route[1])
```

진출 지점을 기준으로 제자리 정렬한 뒤 앞에서부터 한 번 순회한다.

### 상태 변수

모든 카메라 위치나 단속된 차량 목록을 별도로 저장할 필요는 없다. 다음 차량이 이미 단속되는지 판단하려면 가장 최근에 설치한 카메라 위치만 있으면 된다.

- `camera`: 마지막으로 설치한 카메라 위치
- `answer`: 설치한 카메라 개수

작성한 코드의 `stack`은 생성만 하고 사용하지 않는다.

```python
stack = []
```

이 문제는 이전 선택을 되돌리거나 여러 후보를 후입선출로 관리하지 않으므로 스택이 필요하지 않다. 사용하지 않는 변수는 제거하면 알고리즘에 필요한 상태가 더 명확해진다.

## 사용한 알고리즘

### 정렬(Sorting)

차량들을 진출 지점 오름차순으로 정렬한다.

```python
routes.sort(key=lambda route: route[1])
```

가장 빨리 단속 기회가 끝나는 차량부터 처리하기 위한 정렬이다.

### 그리디(Greedy)

아직 단속되지 않은 차량 중 가장 빨리 진출하는 차량의 진출 지점에 카메라를 설치한다.

```python
camera = routes[0][1]
count = 1

for start, end in routes[1:]:
    if start > camera:
        camera = end
        count += 1
```

현재 차량의 진입 지점이 카메라 위치보다 뒤에 있을 때만 새 카메라가 필요하다. 새 카메라도 현재 차량의 가장 오른쪽 지점인 `end`에 설치해 이후 구간과 겹칠 가능성을 최대화한다.

### 구간 스케줄링과의 관계

백준 회의실 배정 문제와 마찬가지로 종료 지점을 기준으로 정렬하지만 목표는 다르다.

```text
회의실 배정: 서로 겹치지 않는 구간을 최대한 많이 선택
단속카메라: 모든 구간을 덮는 점을 최소한으로 선택
```

두 문제 모두 가장 빠른 종료 지점을 먼저 확정하면 이후 선택 공간을 가장 많이 남길 수 있다는 공통된 그리디 성질을 사용한다.

## 시간복잡도

차량 수를 `N`이라고 하자.

- 진출 지점 기준 정렬: `O(N log N)`
- 정렬된 차량 한 번 순회: `O(N)`
- 전체 시간복잡도: **`O(N log N)`**
- 알고리즘에서 직접 사용하는 추가 상태: **`O(1)`**

Python의 리스트 정렬은 내부적으로 추가 메모리를 사용할 수 있지만, 풀이에서 별도의 차량 목록이나 카메라 배열을 만들지는 않는다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[차량 경로 routes 입력]
          |
          v
[진출 지점 오름차순 정렬]
          |
          v
[첫 차량의 진출 지점에 카메라 설치]
[count = 1]
          |
          v
[다음 차량의 진입 지점 확인]
          |
          v
[진입 지점 <= 현재 camera?]
       /                  \
     Yes                  No
      |                    |
      v                    v
[기존 카메라로 단속] [현재 차량 진출 지점에]
[추가 설치 없음]       [새 카메라 설치]
      |              [count += 1]
       \                  /
        v                v
          [다음 차량 확인]
                 |
                 v
          [모든 차량 확인 완료]
                 |
                 v
             [count 반환]
```

## 최종 제출 코드

```python
def solution(routes):
    routes.sort(key=lambda route: route[1])

    camera = routes[0][1]
    count = 1

    for start, end in routes[1:]:
        if start > camera:
            camera = end
            count += 1

    return count
```

프로그래머스에서는 `solution()` 함수만 제출하므로 별도의 입력 및 출력 코드는 필요하지 않다.

## 오늘의 회고(실수한 점 포함)

이번 풀이는 진출 지점순으로 정렬하고 현재 카메라가 다음 차량 경로에 포함되는지 확인하는 그리디 전략을 정확하게 구현했다.

특히 다음 두 선택이 핵심이었다.

```text
가장 빨리 진출하는 차량부터 처리한다.
새 카메라는 해당 차량의 진출 지점에 설치한다.
```

복기할 내용은 다음과 같다.

1. **종료 지점 정렬의 이유를 설명할 수 있어야 한다.**

   단순히 구간 문제에서 자주 사용하는 패턴이라 외우기보다, 가장 빨리 끝나는 차량은 그 지점 이후에는 단속할 수 없고 진출 지점에 카메라를 놓아야 이후 차량과 겹칠 여지를 가장 많이 남긴다는 근거를 기억해야 한다.

2. **진입 지점만 비교해도 되는 이유는 정렬에 있다.**

   현재 카메라가 이후 차량의 진출 지점보다 앞이라는 사실이 정렬로 보장된다. 따라서 `start <= camera`만 확인해도 전체 구간 포함 여부를 판단할 수 있다. 코드에서 생략된 조건이 있다면 다른 불변식이 이를 보장하는지 확인해야 한다.

3. **경계값도 구간에 포함된다.**

   진입·진출 지점에 카메라가 있어도 단속되므로 `start == camera`인 차량은 기존 카메라로 처리한다. 구간 문제에서는 열린 구간인지 닫힌 구간인지에 따라 `<`와 `<=`가 달라진다.

4. **사용하지 않는 `stack`이 남아 있었다.**

   풀이를 고민하는 과정에서 만든 자료구조가 최종 알고리즘에서는 필요하지 않을 수 있다. 제출 전에 사용하지 않는 변수와 import를 제거하면 실제 필요한 상태와 알고리즘이 선명해진다.

5. **`else` 없이 조건을 더 간단히 표현할 수 있다.**

   단속된 차량은 아무 작업도 하지 않으므로 `continue`와 `else`를 함께 쓰기보다, 새 카메라가 필요한 `start > camera`인 경우만 처리할 수 있다.

이번 문제를 통해 여러 구간을 최소 개수의 지점으로 덮는 문제에서는 **종료 지점순으로 정렬하고, 아직 덮이지 않은 가장 빠른 종료 지점에 새 점을 선택하는 그리디 전략**을 우선 검토해야 한다는 점을 복기했다. 또한 정렬이 어떤 비교 조건을 자동으로 보장하는지까지 이해하면 구현을 더 간결하게 만들 수 있다.
