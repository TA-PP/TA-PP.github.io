## 문제 정의

[백준 1781번 컵라면](https://www.acmicpc.net/problem/1781)은 각 문제의 데드라인과 문제를 풀었을 때 받을 수 있는 컵라면 수가 주어질 때, 데드라인을 지키며 받을 수 있는 컵라면의 최대 개수를 구하는 문제다.

문제 하나를 푸는 데는 정확히 하루가 걸리고, 하루에는 문제를 하나만 풀 수 있다. 따라서 데드라인이 `d`인 문제까지 고려했을 때 실제로 풀 수 있는 문제는 최대 `d`개다.

예를 들어 데드라인이 2 이하인 문제를 3개 선택했다면 그중 하나는 반드시 포기해야 한다. 이때 컵라면을 최대한 많이 받으려면 보상이 가장 작은 문제를 제외해야 한다.

`N`이 최대 200,000이므로 매번 선택한 문제 전체를 정렬하거나 최솟값을 선형으로 찾는 방법은 비효율적이다. 현재까지 선택한 보상 중 최솟값을 빠르게 제거할 수 있는 최소 힙이 필요하다.

## 접근 및 설계

작성한 코드는 다음 순서로 문제를 해결한다.

1. 모든 문제를 `[데드라인, 컵라면 수]` 형태로 저장한다.
2. 데드라인이 빠른 문제부터 처리하도록 오름차순 정렬한다.
3. 현재 문제의 컵라면 수를 최소 힙에 추가한다.
4. 선택한 문제 수가 현재 데드라인을 초과하면 컵라면 수가 가장 작은 문제를 제거한다.
5. 모든 문제를 확인한 뒤 힙에 남은 컵라면 수를 합산한다.

```python
cupnoodle.sort()

for noodle in cupnoodle:
    deadline = noodle[0]
    cnt = noodle[1]
    heapq.heappush(heap, cnt)

    while len(heap) > deadline:
        heapq.heappop(heap)
```

이 풀이는 정답 전략을 정확하게 구현했다. 중요한 부분은 문제를 무조건 확정하는 것이 아니라 일단 후보에 넣은 뒤, 마감일 제한을 위반하면 현재 후보 전체에서 가장 가치가 낮은 문제를 취소한다는 것이다.

### 예제 흐름

예제의 문제를 데드라인순으로 정렬하면 다음과 같다.

```text
(데드라인, 컵라면 수)
(1, 6), (1, 7), (2, 4), (2, 5),
(3, 1), (3, 2), (6, 1)
```

초반 처리 과정은 다음과 같다.

```text
(1, 6) 추가 -> [6]
(1, 7) 추가 -> [6, 7]
힙 크기 2 > 데드라인 1 -> 6 제거 -> [7]

(2, 4) 추가 -> [4, 7]
(2, 5) 추가 -> [4, 7, 5]
힙 크기 3 > 데드라인 2 -> 4 제거 -> [5, 7]
```

모든 문제를 처리하면 힙에는 보상 `7, 5, 2, 1`에 해당하는 문제들이 남고 합은 `15`가 된다.

### 왜 `while` 대신 `if`도 가능한가

작성한 코드에서는 다음과 같이 `while`을 사용했다.

```python
while len(heap) > deadline:
    heapq.heappop(heap)
```

이 코드는 올바르다. 다만 문제를 데드라인 오름차순으로 처리하고 한 번의 반복에서 문제 하나만 추가하므로, 힙 크기는 현재 데드라인보다 최대 1만 커질 수 있다.

이전 반복이 끝났을 때 이미 마감일 제한을 만족했고 현재 데드라인은 이전보다 작아지지 않는다. 여기에 문제 하나를 추가했으므로 제거도 최대 한 번만 필요하다.

따라서 최종 코드에서는 조건의 의미를 더 직접적으로 표현하도록 `if`를 사용했다.

```python
if len(rewards) > deadline:
    heapq.heappop(rewards)
```

## 사용한 자료구조

### 리스트(List)

모든 문제의 데드라인과 컵라면 수를 저장한다.

```python
problems = []

for _ in range(N):
    deadline, reward = map(int, input().split())
    problems.append((deadline, reward))
```

입력 순서는 데드라인순이라는 보장이 없으므로 전체 문제를 리스트에 저장한 뒤 정렬한다. 문제 정보를 수정할 필요가 없으므로 최종 코드에서는 리스트 대신 튜플로 각 문제를 표현했다.

### 최소 힙(Min Heap)

힙에는 현재까지 선택한 문제의 컵라면 수만 저장한다.

```python
heapq.heappush(rewards, reward)
```

Python의 `heapq`는 루트인 `rewards[0]`에 최솟값을 두는 최소 힙이다. 현재 마감일까지 풀 수 있는 문제 수를 초과하면 `heapq.heappop()`으로 보상이 가장 작은 문제를 제거할 수 있다.

```python
heapq.heappop(rewards)
```

힙 내부 전체가 정렬된 것은 아니지만, 이 문제에서 필요한 연산은 최솟값의 추가와 제거이므로 최소 힙이면 충분하다.

## 사용한 알고리즘

### 정렬(Sorting)

문제를 데드라인 오름차순으로 정렬한다.

```python
problems.sort()
```

각 문제를 `(deadline, reward)`로 저장했기 때문에 Python의 기본 튜플 정렬은 데드라인을 먼저 비교하고, 데드라인이 같으면 컵라면 수를 비교한다.

같은 데드라인 안에서 보상 순서는 정답에 영향을 주지 않는다. 같은 마감일의 문제를 모두 처리하면서 후보 수가 제한을 넘을 때마다 최소 보상을 제거하면 결국 큰 보상들만 남기 때문이다.

### 그리디(Greedy)

각 문제를 우선 선택 후보에 넣는다. 후보 수가 현재 데드라인을 초과하면 그중 보상이 가장 적은 문제를 제거한다.

```python
for deadline, reward in problems:
    heapq.heappush(rewards, reward)

    if len(rewards) > deadline:
        heapq.heappop(rewards)
```

현재 데드라인이 `d`라면 지금까지 살펴본 문제 중 최대 `d`개만 풀 수 있다. 후보가 `d + 1`개가 되면 최소 하나를 포기해야 한다.

이때 최저 보상이 아닌 다른 문제를 버린 선택이 있다고 가정하자. 버린 문제와 최저 보상 문제를 교체해도 선택한 문제 개수와 데드라인 조건은 변하지 않으며, 컵라면 합은 더 커지거나 같다.

따라서 매 단계에서 가장 작은 보상을 제거하는 선택은 최적해를 해치지 않는다. 모든 문제를 처리한 뒤 힙에는 데드라인을 만족하면서 보상 합이 최대가 되는 문제들만 남는다.

## 시간복잡도

- 문제 `N`개 입력 및 저장: `O(N)`
- 데드라인 기준 정렬: `O(N log N)`
- 문제별 힙 삽입: `O(log N)`
- 필요한 경우 힙 최솟값 제거: `O(log N)`
- 힙에 남은 보상 합산: `O(N)`
- 전체 시간복잡도: **`O(N log N)`**
- 공간복잡도: **`O(N)`**

입력 크기가 최대 200,000이더라도 정렬과 힙 연산으로 처리할 수 있다.

## 최종 제출 코드

```python
import sys
import heapq

input = sys.stdin.buffer.readline

N = int(input())
problems = []

for _ in range(N):
    deadline, reward = map(int, input().split())
    problems.append((deadline, reward))

problems.sort()

rewards = []

for deadline, reward in problems:
    heapq.heappush(rewards, reward)

    if len(rewards) > deadline:
        heapq.heappop(rewards)

print(sum(rewards))
```

## 오늘의 회고(실수한 점 포함)

이번 풀이는 데드라인순 정렬과 최소 힙을 정확하게 조합했다. 문제를 하나씩 후보에 추가하면서 마감일 제한을 넘는 순간 가장 낮은 보상을 제거했기 때문에 별도의 날짜별 스케줄을 만들지 않고도 최적의 문제 집합을 구할 수 있었다.

특히 앞서 풀었던 순회강연 문제와 구조가 같다는 점을 알아볼 수 있다.

```text
순회강연: 마감일 안에 강연을 선택해 강연료 합 최대화
컵라면:   마감일 안에 문제를 선택해 컵라면 합 최대화
```

두 문제 모두 작업 하나에 하루가 걸리고, 작업마다 마감일과 보상이 있으며, 전체 보상을 최대화한다. 문제의 소재가 달라도 제약과 목표를 추상화하면 같은 그리디 패턴을 재사용할 수 있다.

제출 코드를 더 명확하게 다듬을 부분은 다음과 같다.

1. **`cnt`의 의미가 모호했다.**

   `cnt`는 일반적으로 개수를 세는 변수처럼 보이지만 여기서는 문제 하나의 컵라면 보상이다. `reward`처럼 역할이 드러나는 이름을 사용하면 `heap`에 어떤 값이 들어가는지 바로 알 수 있다.

2. **`while`은 맞지만 `if`로 충분했다.**

   문제를 한 번에 하나씩 추가하므로 제한을 초과해도 한 개만 제거하면 된다. 현재 코드의 `while`도 정답이지만 불변식을 이해했다는 점을 드러내려면 `if`가 더 간결하다.

3. **직접 합산하는 반복문을 줄일 수 있었다.**

   ```python
   answer = 0
   for value in heap:
       answer += value
   ```

   Python에서는 `sum(rewards)`로 합계를 바로 구할 수 있어 코드의 목적이 더 분명해진다.

4. **자료구조 이름에 역할을 담을 수 있었다.**

   `cupnoodle`, `heap`도 동작하지만 `problems`, `rewards`라고 표현하면 각각 전체 문제 목록과 현재 선택된 보상이라는 역할을 쉽게 구분할 수 있다.

이번 문제를 통해 **마감일이 있는 단위 시간 작업의 보상 최대화** 문제에서는 마감일순으로 정렬하고, 선택한 보상을 최소 힙에 유지하면서 제한을 초과할 때 최솟값을 제거하는 전략을 다시 확인했다. 풀이를 외우기보다 “현재 마감일까지 선택 가능한 개수”와 “하나를 버린다면 무엇을 버릴 것인가”라는 두 질문으로 그리디 선택을 도출하는 것이 중요하다.
