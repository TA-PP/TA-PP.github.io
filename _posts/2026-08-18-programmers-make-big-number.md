## 문제 정의

[프로그래머스 큰 수 만들기](https://school.programmers.co.kr/learn/courses/30/lessons/42883)는 문자열로 주어진 숫자 `number`에서 정확히 `k`개의 숫자를 제거했을 때 만들 수 있는 가장 큰 수를 문자열로 반환하는 문제다.

숫자의 순서를 바꿀 수는 없다. 원래 순서를 유지한 채 일부 자리만 제거해야 한다.

```text
number = "1924", k = 2

가능한 결과:
19, 12, 14, 92, 94, 24

가장 큰 수: 94
```

`number`의 길이는 최대 1,000,000이다. 모든 삭제 조합을 직접 만들고 비교하는 완전탐색은 사용할 수 없으며, 숫자를 한 번 순회하면서 제거할 위치를 결정해야 한다.

## 접근 및 설계

### 1차 풀이: 모든 조합을 생성해 최댓값 찾기

처음에는 전체 숫자 중 `len(number) - k`개를 선택하는 모든 조합을 생성했다.

```python
temp = list(combinations(number, len(number) - k))
```

각 조합을 문자열로 합치고 정수로 바꾼 뒤 음수로 최소 힙에 넣었다.

```python
for i in temp:
    heapq.heappush(heap, -int(''.join(i)))

temp_answer = heapq.heappop(heap)
answer = str(-temp_answer)
```

`itertools.combinations`는 선택한 문자의 원래 순서를 유지하므로 문제에서 만들 수 있는 모든 후보를 생성한다는 점에서는 맞는 접근이다. 작은 입력에서는 실제 최댓값도 구할 수 있다.

하지만 입력 크기를 감당할 수 없다.

원본 길이를 `N`, 남겨야 할 자릿수를 `N - K`라고 하면 후보 개수는 다음과 같다.

```text
C(N, N-K) = C(N, K)
```

예를 들어 `N = 30`, `K = 15`만 되어도 후보 수는 155,117,520개다. 문제의 최대 길이는 100만이므로 조합 생성 자체가 불가능하다.

또한 `list()`로 모든 조합을 한꺼번에 저장해 메모리 사용량이 더 커진다. 각 후보를 긴 문자열로 합치고 큰 정수로 변환하며 힙에 모두 보관하는 비용도 추가된다.

이 문제는 최댓값 하나만 필요하므로 완전탐색을 하더라도 힙에 모든 후보를 저장할 이유는 없다. 하지만 힙을 없애고 현재 최댓값만 저장해도 조합 개수 자체가 너무 많다는 근본 문제는 해결되지 않는다.

### 2차 풀이: 앞자리의 작은 숫자를 스택에서 제거

가장 큰 수를 만들려면 가능한 한 큰 숫자를 앞자리에 배치해야 한다. 같은 길이의 두 숫자는 처음으로 다른 자릿수에서 더 큰 숫자를 가진 쪽이 항상 더 크기 때문이다.

문자열을 왼쪽부터 읽다가 현재 숫자가 스택의 마지막 숫자보다 크다면, 앞의 작은 숫자를 제거하고 현재 숫자를 한 자리 앞으로 보내는 것이 유리하다.

```python
while k > 0 and stack and stack[-1] < digit:
    stack.pop()
    k -= 1
```

제거할 수 있는 횟수가 남아 있고 스택 끝의 숫자가 현재 숫자보다 작은 동안 반복해서 제거한다. 이후 현재 숫자를 스택에 추가한다.

```python
stack.append(digit)
```

### 수정 코드의 변수명 오류

작성한 두 번째 코드에서는 반복 변수로 `s`를 선언했지만 조건과 추가에서는 `i`를 사용했다.

```python
for s in number:
    while k > 0 and stack and stack[-1] < i:
        stack.pop()
        k -= 1

    stack.append(i)
```

`i`는 함수 안에서 정의되지 않았으므로 그대로 실행하면 `NameError`가 발생한다. 반복 변수 이름을 `digit`으로 통일하면 된다.

```python
for digit in number:
    while k > 0 and stack and stack[-1] < digit:
        stack.pop()
        k -= 1

    stack.append(digit)
```

### 예제 흐름: `1924`에서 2개 제거

```text
초기 상태: stack = [], k = 2

1 입력
stack = [1]

9 입력
1 < 9 이므로 1 제거, k = 1
stack = [9]

2 입력
9 < 2가 아니므로 유지
stack = [9, 2]

4 입력
2 < 4 이므로 2 제거, k = 0
stack = [9, 4]

결과: "94"
```

### 왜 앞의 작은 숫자를 제거하는가

스택의 마지막 숫자를 `x`, 현재 숫자를 `y`라고 하고 `x < y`라고 하자.

`x`를 남기고 뒤쪽의 다른 숫자를 제거하면 결과의 해당 앞자리에는 `x`가 남는다. 반대로 `x`를 제거하면 더 큰 `y`가 한 자리 앞으로 이동한다.

```text
x를 유지: ... x y ...
x를 제거: ... y ...

x < y
```

두 결과에서 처음 달라지는 위치에 `x`와 `y`가 놓이므로 `y`를 앞당긴 결과가 뒤의 숫자와 관계없이 더 크다. 따라서 제거 횟수가 남아 있다면 앞의 작은 숫자를 제거하는 선택은 항상 이득이다.

### 제거 횟수가 남는 경우

숫자가 내림차순이거나 같은 숫자가 이어지면 앞의 숫자보다 큰 현재 숫자를 만나지 못할 수 있다.

```text
number = "654321", k = 2
```

이 경우 순회 중에는 아무 숫자도 제거되지 않는다. 이미 큰 숫자가 앞에 배치되어 있으므로 가장 작은 자릿수 영향을 주는 뒤쪽 숫자부터 제거해야 한다.

```python
if k > 0:
    stack = stack[:-k]
```

결과는 `6543`이 된다.

이 후처리는 반드시 필요하다. 스택에서 작은 앞자리 숫자를 제거하는 동안 `k`가 항상 0이 된다는 보장은 없다.

## 사용한 자료구조

### 조합(Combinations)

첫 풀이에서는 `itertools.combinations`로 남길 숫자의 모든 경우를 생성했다.

```python
combinations(number, len(number) - k)
```

순서를 유지하는 부분수열을 생성하므로 문제 정의와는 맞지만, 조합 수가 `C(N, K)`로 증가해 큰 입력에서는 사용할 수 없다.

특히 이를 `list()`로 감싸면 지연 생성의 장점도 사라지고 모든 조합이 동시에 메모리에 올라간다.

### 힙(Heap)

첫 풀이에서는 Python 최소 힙에 후보의 음수값을 저장해 최대값을 꺼냈다.

```python
heapq.heappush(heap, -candidate)
```

최대 힙을 흉내 내는 사용법 자체는 맞지만, 이 문제에서는 모든 후보를 보관할 필요가 없다. 가장 큰 후보 하나만 필요하며, 더 근본적으로 후보 전체를 생성해서는 제한을 통과할 수 없다.

### 스택(Stack)

최종 풀이에서는 현재까지 선택한 숫자를 리스트 스택에 저장한다.

```python
stack.append(digit)
stack.pop()
```

제거 횟수가 남아 있는 동안 스택 끝에는 현재 숫자보다 작은 숫자가 남지 않도록 관리한다. 새 숫자가 더 크면 앞의 작은 후보를 제거해 큰 숫자를 앞으로 이동시킨다.

각 숫자는 스택에 한 번 들어가고 최대 한 번 제거된다.

## 사용한 알고리즘

### 그리디(Greedy)

현재 숫자가 이전에 선택한 마지막 숫자보다 크다면 이전 숫자를 제거한다. 가장 앞에서 처음 달라지는 숫자가 전체 크기를 결정하므로, 가능한 큰 숫자를 앞자리로 보내는 선택이 전체 최댓값으로 이어진다.

```python
for digit in number:
    while k > 0 and stack and stack[-1] < digit:
        stack.pop()
        k -= 1

    stack.append(digit)
```

현재 순간에 작은 숫자를 제거하지 않고 나중 숫자를 제거하는 선택은 더 작은 앞자리를 확정하므로 최적해가 될 수 없다.

### 단조 스택 패턴

제거 횟수가 남아 있는 동안 현재 숫자보다 작은 스택 꼬리를 제거한다. 이 과정에서 선택 후보는 큰 숫자가 앞에 오도록 정리된다.

다만 `k`가 0이 된 이후에는 더 이상 제거할 수 없으므로 남은 숫자를 순서대로 모두 추가한다. 따라서 전체 실행 내내 완전한 단조 상태를 유지하는 것이 목적이라기보다, **제거 예산을 사용해 앞자리의 증가 구간을 정리하는 스택 그리디**라고 이해하는 것이 정확하다.

## 시간복잡도

원본 숫자의 길이를 `N`이라고 하자.

### 조합 풀이

- 생성 후보 수: `C(N, K)`
- 후보 하나 결합 및 변환: 최대 `O(N)`
- 모든 후보의 힙 삽입: 후보마다 로그 비용 추가
- 시간복잡도와 공간복잡도 모두 조합 수에 비례해 폭발

최대 100만 자리 입력에서는 실행할 수 없다.

### 스택 풀이

- 숫자 `N`개 순회: `O(N)`
- 각 숫자 스택 추가: 최대 한 번
- 각 숫자 스택 제거: 최대 한 번
- 남은 `k`개 뒤쪽 제거 및 문자열 결합: `O(N)`
- 전체 시간복잡도: **`O(N)`**
- 공간복잡도: **`O(N)`**

`for`문 안에 `while`문이 있지만 한 번 제거된 숫자는 다시 스택에 들어가지 않는다. 전체 `pop()` 횟수는 최대 `N`번이다.

## 알고리즘 흐름(텍스트 다이어그램)

```text
[number의 숫자를 왼쪽부터 하나씩 확인]
                    |
                    v
          [제거 횟수 k > 0 인가?]
              /               \
            No                Yes
             |                 |
             |                 v
             |          [스택이 비었는가?]
             |             /          \
             |           Yes          No
             |            |            |
             |            |            v
             |            |   [stack[-1] < 현재 숫자?]
             |            |        /             \
             |            |      Yes             No
             |            |       |               |
             |            |       v               |
             |            |   [스택 pop]           |
             |            |   [k -= 1]            |
             |            |       |               |
             |            | [조건 다시 확인]       |
             |            \       |              /
             |             \      v             /
             +--------------> [현재 숫자 push]
                                |
                                v
                         [다음 숫자 확인]
                                |
                                v
                       [모든 숫자 처리 완료]
                                |
                                v
                         [k가 남아 있는가?]
                           /           \
                         Yes           No
                          |             |
                          v             |
                  [스택 뒤에서 k개 제거]|
                          \            /
                           v          v
                       [문자열로 합쳐 반환]
```

## 최종 제출 코드

```python
def solution(number, k):
    stack = []

    for digit in number:
        while k > 0 and stack and stack[-1] < digit:
            stack.pop()
            k -= 1

        stack.append(digit)

    if k > 0:
        stack = stack[:-k]

    return ''.join(stack)
```

프로그래머스에서는 `solution()` 함수만 제출하므로 별도의 입력 코드나 출력 코드는 필요하지 않다.

## 오늘의 회고(실수한 점 포함)

첫 풀이에서는 문제 설명을 그대로 따라 `k`개를 제거하는 모든 경우를 생성했다. 정답을 구하는 방식 자체는 직관적이지만 입력 길이를 확인하기 전에 완전탐색을 선택해 시간 초과가 발생했다.

두 번째 풀이에서는 큰 숫자를 앞자리로 보내는 스택 그리디로 전환하면서 알고리즘의 방향을 올바르게 수정했다.

이번 풀이에서 복기할 내용은 다음과 같다.

1. **입력 제한보다 먼저 조합을 선택했다.**

   `combinations`를 사용할 때는 `C(N, K)`가 실제로 어느 정도 크기인지 계산해야 한다. `N`이 최대 100만인 문제에서 모든 조합 생성은 불가능하다.

2. **모든 조합을 리스트로 저장했다.**

   `itertools.combinations`는 원래 지연 생성되지만 `list()`로 감싸 모든 결과를 메모리에 올렸다. 시간뿐 아니라 메모리도 급격히 증가한다.

3. **최댓값 하나를 위해 힙에 모든 후보를 넣었다.**

   힙은 여러 후보 중 우선순위가 높은 값을 반복해서 꺼낼 때 유용하다. 이 문제는 최댓값 하나만 필요하므로 완전탐색을 유지하더라도 힙은 불필요했다. 자료구조를 사용하기 전에 필요한 연산이 무엇인지 확인해야 한다.

4. **수정 코드의 반복 변수 이름이 일치하지 않았다.**

   `for s in number`라고 선언한 뒤 `i`를 사용해 실행 시 오류가 발생한다. 알고리즘을 수정한 뒤에는 변수명까지 한 흐름으로 읽으며 실행 가능한지 확인해야 한다.

5. **순회 중 `k`를 모두 사용하지 못하는 경우가 있다.**

   내림차순이나 같은 숫자가 반복되면 스택에서 제거가 일어나지 않는다. 남은 제거 횟수만큼 뒤쪽 숫자를 잘라야 정확히 `k`개를 제거할 수 있다.

6. **앞자리의 중요성을 그리디 기준으로 연결할 수 있었다.**

   같은 길이의 숫자는 가장 앞에서 다른 자릿수가 큰 쪽이 더 크다. 이 성질 때문에 앞의 작은 숫자를 제거하고 뒤의 큰 숫자를 당기는 선택이 항상 유리하다.

이번 문제를 통해 조합으로 모든 결과를 만들어 비교하는 문제가 시간 초과를 일으킬 때는, 최댓값의 순서를 결정하는 **가장 앞의 차이**를 기준으로 선택을 즉시 확정할 수 있는지 확인해야 한다는 점을 복기했다. 또한 앞자리의 작은 값을 제거하는 유형에서는 스택 그리디를 우선 떠올릴 수 있다.
