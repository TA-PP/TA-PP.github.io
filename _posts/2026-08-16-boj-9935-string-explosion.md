## 문제 정의

[백준 9935번 문자열 폭발](https://www.acmicpc.net/problem/9935)은 원본 문자열 안에 포함된 폭발 문자열을 모두 제거하고, 제거 과정에서 새롭게 만들어진 폭발 문자열도 더 이상 남지 않을 때까지 연쇄적으로 삭제하는 문제다.

폭발 과정은 다음과 같다.

1. 문자열에 포함된 모든 폭발 문자열이 사라진다.
2. 삭제된 부분의 앞뒤 문자열이 이어지면서 새로운 폭발 문자열이 만들어질 수 있다.
3. 폭발 문자열이 남아 있지 않을 때까지 이 과정을 반복한다.
4. 최종 문자열이 비었다면 `FRULA`를 출력한다.

원본 문자열의 길이는 최대 1,000,000이고 폭발 문자열의 길이는 최대 36이다. 문자열 전체를 계속 탐색하고 삭제할 때마다 새 문자열을 만들면 시간과 메모리 사용량이 크게 증가한다.

## 접근 및 설계

### 1차 풀이: 문자열 전체를 반복 탐색

처음에는 모든 시작 위치에서 폭발 문자열과 같은 부분 문자열을 찾고, 발견할 때마다 앞부분과 뒷부분을 이어 붙였다.

```python
while True:
    for i in range(len(string) - len(explode) + 1):
        if string[i:i + len(explode)] == explode:
            string = string[0:i] + string[i + len(explode):]
            count += 1

    if count != 0:
        count = 0
    else:
        break
```

폭발로 인해 새로운 문자열이 만들어지는 경우를 처리하기 위해 한 번이라도 삭제했다면 전체를 다시 탐색한다는 접근이었다. 결과를 직접 시뮬레이션한다는 점에서는 자연스럽지만 큰 입력을 처리하기 어렵다.

Python의 문자열은 불변 객체다. 다음 코드는 기존 문자열의 일부만 지우는 것이 아니라 두 개의 부분 문자열과 이들을 합친 새 문자열을 만든다.

```python
string = string[0:i] + string[i + len(explode):]
```

문자 하나하나를 검사하면서 부분 문자열을 생성하고, 폭발할 때마다 긴 문자열을 다시 복사하며, 한 번의 순회가 끝난 뒤에도 폭발이 있었다면 처음부터 다시 확인한다. 원본 길이가 최대 100만이므로 이 방식은 시간 초과가 발생하기 쉽다.

문자열을 순회하는 도중 `string`의 길이가 바뀌는데 `range()`는 반복문 시작 시의 길이로 이미 만들어졌다는 점도 코드를 이해하기 어렵게 만든다. 삭제 직후 건너뛴 위치에서 생긴 폭발은 다음 전체 순회에서야 처리된다.

### 2차 풀이: 스택에 살아남은 문자만 유지

수정한 풀이에서는 원본 문자열을 왼쪽부터 한 번 순회하면서 지금까지 폭발하지 않고 남은 문자만 스택에 저장했다.

```python
for s in string:
    stack.append(s)

    if stack[-len(explode):] == explode:
        del stack[-len(explode):]
```

새 문자를 스택 끝에 추가했을 때 새로 생길 수 있는 폭발 문자열은 반드시 **현재 스택의 끝**에 있다. 이미 처리한 앞부분에 폭발 문자열이 남아 있었다면 그 앞 단계에서 제거됐어야 하기 때문이다.

따라서 매번 문자열 전체를 다시 탐색하지 않고 다음 두 단계만 수행하면 된다.

1. 현재 문자를 스택에 추가한다.
2. 스택의 마지막 `M`개 문자가 폭발 문자열과 같으면 바로 제거한다.

여기서 `M`은 폭발 문자열의 길이다.

### 연쇄 폭발도 바로 처리되는 이유

폭발 문자열을 스택에서 제거하면 삭제된 구간 앞의 문자들이 다시 스택 끝이 된다. 이후 다음 문자가 추가될 때 이 새 경계를 포함한 꼬리를 다시 검사하므로, 앞뒤 문자열이 이어져 생기는 연쇄 폭발도 별도의 전체 재탐색 없이 처리된다.

예를 들어 원본이 `12ab112ab2ab`, 폭발 문자열이 `12ab`라면 다음과 같이 처리된다.

```text
12ab 발견 -> 제거
남은 처리 결과: 1

다음 문자들을 추가
1 + 12ab 중 뒤의 12ab 발견 -> 제거
남은 처리 결과: 1

남은 2ab가 붙음
1 + 2ab = 12ab -> 새 폭발 발생
최종 결과: 빈 문자열
```

삭제 후 생긴 새 경계가 스택 끝에 위치하기 때문에 연쇄 폭발이 자연스럽게 이어진다.

### 마지막 문자로 불필요한 비교 줄이기

폭발 문자열이 완성되려면 현재 추가한 문자가 폭발 문자열의 마지막 문자와 같아야 한다. 따라서 마지막 문자가 다르면 스택 꼬리 슬라이스를 만들 필요가 없다.

```python
if (
    char == bomb_last
    and len(stack) >= bomb_length
    and stack[-bomb_length:] == bomb
):
    del stack[-bomb_length:]
```

이 조건은 최악 시간복잡도의 차수를 바꾸지는 않지만 실제 비교와 임시 리스트 생성을 줄인다.

## 사용한 자료구조

### 문자열(String)

첫 풀이에서는 원본과 현재 결과를 모두 문자열로 관리했다. 인덱스 슬라이싱으로 부분 문자열을 비교하는 것은 간단하지만, 문자열 중간을 제거할 때마다 전체 결과를 새로 생성해야 한다.

```python
string[:i] + string[i + bomb_length:]
```

문자열의 길이가 크고 삭제가 반복되는 상황에서는 중간 수정에 적합하지 않다.

### 스택(Stack)

최종 풀이에서는 Python 리스트를 스택으로 사용한다.

- `append()`: 새 문자를 스택 끝에 추가한다.
- `stack[-M:]`: 마지막 `M`개 문자를 확인한다.
- `del stack[-M:]`: 완성된 폭발 문자열을 제거한다.

스택에는 지금까지 읽은 원본 문자열의 접두사에서 모든 폭발을 처리한 결과만 남는다. 이것이 반복문 전체에서 유지해야 하는 핵심 불변식이다.

폭발 문자열도 문자 리스트로 변환하면 스택의 마지막 구간과 바로 비교할 수 있다.

```python
bomb = list(input().rstrip())
```

## 사용한 알고리즘

### 스택 기반 문자열 처리

원본 문자열을 왼쪽부터 읽으며 현재까지 살아남은 문자를 스택에 쌓는다. 새 문자를 추가한 뒤 스택 끝이 폭발 문자열과 일치하면 그 구간을 삭제한다.

```python
for char in source:
    stack.append(char)

    if stack[-bomb_length:] == bomb:
        del stack[-bomb_length:]
```

폭발 후보가 새로 생길 수 있는 위치를 스택 끝으로 제한함으로써 문자열 전체를 반복 탐색하지 않는다.

### 시뮬레이션(Simulation)

문제에 설명된 폭발 순서를 그대로 구현하지만 실제 문자열 전체를 매 단계 생성하지 않는다. 스택을 “현재까지 폭발이 모두 끝난 문자열”로 사용해 필요한 상태만 유지한다.

각 문자를 처리한 뒤 스택에는 폭발 문자열이 존재하지 않는다는 불변식이 성립한다. 마지막 문자 추가로 폭발 문자열이 생겼다면 즉시 제거하므로, 전체 순회가 끝난 스택이 모든 연쇄 폭발 이후의 최종 결과다.

## 시간복잡도

원본 문자열 길이를 `N`, 폭발 문자열 길이를 `M`이라고 하자.

### 첫 번째 풀이

- 한 번의 전체 탐색에서 여러 부분 문자열을 생성하고 비교한다.
- 폭발할 때마다 문자열 앞뒤를 복사해 새 문자열을 만든다.
- 삭제가 있었다면 다시 문자열 전체를 탐색한다.

반복 횟수와 삭제 위치에 따라 비용이 크게 증가하며, 문자열 복사와 전체 재탐색이 중첩되므로 큰 입력에서는 사실상 사용할 수 없다.

### 스택 풀이

- 원본 문자 `N`개 순회: `O(N)`
- 스택 꼬리 슬라이스 생성과 폭발 문자열 비교: 한 번에 `O(M)`
- 폭발 구간 삭제: 한 번에 최대 `O(M)`
- 전체 시간복잡도: **`O(NM)`**
- 공간복잡도: **`O(N)`**

이 문제에서 `M`은 최대 36이므로 비교 길이가 작게 제한된다. 따라서 실질적으로는 원본 문자열 길이에 비례하는 방식으로 동작한다.

스택 풀이를 단순히 `O(N)`이라고 정리하기 쉽지만 Python의 `stack[-M:]`는 새 리스트를 만들고 원소를 비교하므로 엄밀하게는 `O(NM)`이다.

## 최종 제출 코드

```python
import sys

input = sys.stdin.readline

source = input().rstrip()
bomb = list(input().rstrip())

bomb_length = len(bomb)
bomb_last = bomb[-1]
stack = []

for char in source:
    stack.append(char)

    if (
        char == bomb_last
        and len(stack) >= bomb_length
        and stack[-bomb_length:] == bomb
    ):
        del stack[-bomb_length:]

result = ''.join(stack)
print(result if result else 'FRULA')
```

## 오늘의 회고(실수한 점 포함)

첫 풀이에서는 문제 설명의 “폭발 문자열이 없을 때까지 반복한다”를 그대로 `while True`로 구현했다. 동작을 직관적으로 옮겼다는 장점은 있지만, 문자열의 중간 삭제와 전체 재탐색이 큰 입력에서 얼마나 비싼지 고려하지 못했다.

두 번째 풀이에서 스택으로 전환한 것은 핵심적인 개선이었다. 지금까지 처리한 결과만 유지하고 새 폭발 가능성을 스택 끝에서만 검사해 연쇄 반응을 효율적으로 처리했다.

이번 풀이에서 확인한 부분은 다음과 같다.

1. **Python 문자열은 중간에서 직접 수정할 수 없다.**

   슬라이싱과 `+`로 삭제를 표현할 때마다 새 문자열이 만들어진다. 입력이 큰 문자열 문제에서는 반복적인 이어 붙이기보다 리스트나 스택 사용을 먼저 검토해야 한다.

2. **전체 문자열을 다시 찾을 필요가 없었다.**

   왼쪽부터 이미 폭발 처리가 끝난 상태라면 새 문자를 추가한 뒤 확인할 위치는 스택 끝뿐이다. “새로운 변화가 생길 수 있는 위치”를 좁히는 것이 시간복잡도 개선의 핵심이었다.

3. **빈 문자열 출력 조건을 놓쳤다.**

   작성한 두 번째 코드는 결과가 비었을 때 `print(''.join(stack))`으로 빈 줄을 출력한다. 문제에서는 반드시 `FRULA`를 출력해야 한다.

   ```python
   result = ''.join(stack)
   print(result if result else 'FRULA')
   ```

4. **스택 풀이도 엄밀하게는 `O(NM)`이다.**

   마지막 구간을 슬라이싱하고 폭발 문자열과 비교하는 비용이 있다. 다만 폭발 문자열 길이가 최대 36으로 제한되어 있어 이 풀이로 충분하다. 복잡도를 정리할 때 라이브러리 문법 한 줄의 내부 비용도 확인해야 한다.

5. **불필요한 꼬리 비교를 줄일 수 있었다.**

   현재 문자가 폭발 문자열의 마지막 문자와 다르면 폭발이 완성될 수 없다. 마지막 문자를 먼저 확인하면 대부분의 반복에서 슬라이스 생성을 피할 수 있다.

이번 문제를 통해 연속된 패턴을 삭제하면서 새 경계에서 같은 패턴이 다시 생기는 문제는 **스택에 현재까지 살아남은 결과를 유지하고 끝부분만 검사하는 방식**으로 해결할 수 있다는 점을 복기했다. 문자열 삭제 문제를 보면 실제 문자열을 계속 재생성하기 전에, 삭제되지 않은 문자만 스택에 쌓는 관점으로 바꿀 수 있는지 먼저 확인해야 한다.
